## Goal
`nexus-agent` runs inside a self-hosted install (`NEXUS_INSTALL_MODE=self_hosted`) as the database owner:
- **Licence:** reads `licence.json` and the pinned `licence-keys.json` from the install folder, verifies offline, and
  computes the summary the M84 screen shows (edition, state, expiry, support end, learner / campus caps and **counts**
  — counts only, V-7). A missing, unreadable or tampered licence never deletes or locks data: state `read_only`
  with the reason.
- **Updates:** looks in the install's `inbox/` for offline bundles and offers the newest one that verifies against the
  pinned `release-keys.json`, is newer than the running version and allows an upgrade from it (`minUpgradeFrom`);
  "covered by support" = the licence's support end is on or after the release date. Unsigned, tampered or unsafe
  bundles are never offered. (Online checks against Control come with the releases API, NEX-109.)
- **State:** one install-wide row `install_status` (no tenant data) and, for every tenant, the core entitlement `M84`,
  so the existing menu and module guard work.

The product backend serves the frozen M84 screen: `GET /api/v1/install/status`, `/install/update`,
`/install/backups`, `/install/diagnostics` (institution admins, `m01.institution.manage`; `403 module_disabled`
outside a self-hosted install). Backups and diagnostics answer empty lists until NEX-112.
