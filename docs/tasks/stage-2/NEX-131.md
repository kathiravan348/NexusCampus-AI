## Goal
A signed `access_request.file` command files a pending access request in the tenant's own M83 inbox (exactly what the
dev broker stand-in does today), and every later decision the institution makes there is reported back to Control.

## Build
1. `broker_inbox.file_access_request(session, ctx, request)`: the stub's insert + `m83.accessRequest.filed` audit,
   moved here with the id given by Control (`acr-…`); an id that already exists → no-op (idempotent). The dev stub
   keeps working through it.
2. Agent kind `access_request.file`: validate args strictly (same rules as the stub: modules known, no duplicates,
   never M83, 1–72 h, reason 1–2000 chars, staff name ≤ 200); the tenant must exist on this deployment (else
   `failed` with reason `unknown_tenant`); file it in a tenant transaction; result `{requestId}` only.
3. `0021_broker_reports`: `broker_reports` (request id PK, last reported status, reported_at) — install-level, no
   tenant data; app role SELECT, INSERT, UPDATE.
4. Each `commands` run (and `loop`): for requests filed through commands whose M83 status changed since the last
   report (approved, denied, expired, revoked), POST them to `/agent/access-decisions` (≤ 50 per call) through
   `control_endpoint`; record what was accepted. Only ids, statuses and times leave — never the reason or modules.
5. The institution's approve / deny flow in M83 is unchanged; nothing here can approve anything.
