# NEX-129 — Control → deployment commands, agent side (D60): fetch, verify, run once, report

**Status:** planned · **Owner:** — · **Branch:** task/NEX-129 · **Depends on:** NEX-128
**Requirements:** D60, D22, M84, V-1, V-6, V-7

## Goal
`nexus-agent commands` (and each `loop` run) fetches its deployment's commands from Control and runs only those that
are signed by Control, meant for this deployment, unexpired, never seen before and of an allowed kind, then reports
the result. Self-hosted installs keep it off until the institution switches it on; SaaS cells (ours) have it on.

## Build
1. Settings: `deployment_id` (this deployment's Control id; empty = commands off) and `agent_commands` (`on` / `off`;
   default `off` when `install_mode` is `self_hosted`, `on` for `saas` — the institution decides on its own install).
   Never when air-gapped or without a token. Pinned public keys in `install_dir/command-keys.json`; missing = off.
2. `0020_agent_commands`: `agent_commands` (command id PK, kind, received_at, status, finished_at) — the replay
   guard; no tenant data. App role: SELECT, INSERT, UPDATE (status, finished_at).
3. `commands.py`: GET through `control_endpoint` (TLS verified, 10 s, no redirects, body ≤ 64 KB). For each item:
   `verify_command` with the pinned keys; `deploymentId` must equal `deployment_id`; insert the id first (already
   there → skip: never run twice); kind must be in the agent's allow-list (`ping` only here). A bad signature, wrong
   deployment or unknown kind is reported `rejected` and logged by id — its contents are never acted on. Run, then
   report `done` / `failed` with ids, counts or versions only.
4. `ping` → `{"version": app_version}`. `run.py`: mode `commands`; `loop` runs it after the health report. Mode
   `commands` may run when `install_mode` is `saas` (cells); every other mode stays self-hosted only. Prints ids and
   counts only.

## Acceptance checks
- [ ] Tests (fake HTTP): a valid ping runs once and reports `done`; the same id again is skipped; tampered, expired,
  other deployment, unknown key → `rejected`, never run; unknown kind → `rejected`; off / air-gapped / no token / no
  keys → no request at all; a redirect, or http to a non-loopback host, is refused; output prints no person.
- [ ] `uv run --project backend backend-check` and `fnm exec --using=24 -- pnpm --dir frontend review:check` pass.
- [ ] Live: control backend on the dev DB; `nexus-control-command ping dep-in-1`; agent with that token,
  `NEXUS_DEPLOYMENT_ID=dep-in-1`, commands on and the dev public key pinned → Control row `done` with the version;
  run again → nothing re-run; tokens, rows and the pinned file removed afterwards.
