# NEX-139 — Control: an expired command fails its job step, so staff can retry (D63)

**Status:** planned · **Owner:** — · **Branch:** task/NEX-139 · **Depends on:** NEX-136, NEX-107 (same files)
**Requirements:** D60, D61, D63, P04, P10, P18, V-6; follow-up of the NEX-132 / NEX-134 reviews

## Goal
When a signed command expires before its cell runs it, Control fails the step that waited for it, so the job can be
retried instead of staying `pending` / `running` for ever, also when the cell never polls again.

## Build
1. `command_expiry.py`: `expire_commands(conn, vault, cfg, now, deployment_id=None) -> int` takes `pending` /
   `delivered` rows past `expires_at` (`FOR UPDATE SKIP LOCKED`, max 100), sets `expired`, and per kind, in the same
   transaction: `tenant.provision` → `apply_provisioning_result(…, "failed", {"reason": "command_expired"})`;
   `tenant.freeze` / `tenant.export` / `tenant.destroy_keys` / `tenant.import_key` / `tenant.import` → the existing
   offboarding or move result handlers with `failed`; `access_request.file` → its broker request `expired`
   (`decided_at` = now) if still `pending`; `ping` → nothing. Each row is handled once. Log ids, kind and outcome only.
2. `commands.py`: the fetch sweep and the late-result 409 path both call `expire_commands` (no second way to expire).
3. Sweep loop: in `main.py`'s lifespan, a task runs `expire_commands` every `NEXUS_CONTROL_COMMAND_SWEEP_SECONDS`
   (default 60; `0` = off), only when the app opened its own engine; errors are logged by type and the loop goes on.
   `nexus-control-command sweep` runs it once and prints the count.
4. `POST /offboarding-jobs/{id}/retry` (`ctl.provisioning.manage`, partners 404): only a `failed` job; re-queues the
   failed step's command (`tenant.freeze`, `tenant.export` with the stored PEM, or `tenant.destroy_keys` with the two
   approvals already given); 409 otherwise. Keep `recipient_pem` until the export succeeds (as NEX-136 moves).
5. `ControlSettings.command_sweep_seconds`; nothing else changes the contracts (D56: no UI change).

  `access_request.file` → request `expired`; a done job is never touched; running the sweep twice changes nothing;

  never fetch it → row `expired` within the next sweep; reset afterwards.

## Out of scope
