# NEX-141 — Nexus Control P04: buttons for retry, start offboarding, export received and the two approvals

**Status:** ready-for-review · **Owner:** Gemini · **Branch:** task/NEX-141 · **Depends on:** NEX-134, NEX-139
**Requirements:** P04, D61, D63, D65 (Owner OK to change the frozen P04 screens), D8, D42, WCAG 2.2 AA

## Goal
Staff do every P04 step from the Provisioning page, in demo and real mode: retry provisioning, start offboarding,
confirm the export was received, approve key destruction (two people) and retry offboarding — no API calls by hand.

## Build
1. Contract `OffboardingRequestSchema` `{accountId, tenantId, recipientPem}` (PEM text 64–1900 chars), exactly as the
   backend body; test against a mock sample.
2. Services hooks (each refetches the P04 lists): `useRetryProvisioning(jobId)`, `useStartOffboarding()`,
   `useConfirmDownload(jobId)`, `useApproveDestroy(jobId)`, `useRetryOffboarding(jobId)` → `ProvisioningJob` /
   `OffboardingJob`.
3. Screens (shown only with `ctl.provisioning.manage`; a failed request keeps the screen's error state):
   - New tenants: **Retry** on a `failed` job. **Run next step** stays demo-only — hidden when `DATA_MODE` is `real`.
   - Offboarding: **Start offboarding** opens a modal (account, one of its tenants, the institution's public key as
     pasted PEM text, a required tick "the institution's data will be frozen"); **Export received** when
     `export_ready` is done and `export_downloaded` pending; **Approve key destruction** when `export_downloaded` is
     done and `keys_destroyed` pending — a confirm dialog says it cannot be undone and needs a second staff member; on
     success a toast says whether the approval was the first or the destruction is now queued (409 "same person" →
     its own message); **Retry** on a `failed` job. All texts `p04.*` keys with `hi` / `ta`; real `<button>`s; 360 px.
4. Mocks mirror the backend rules: create (RSA key check → 400), freeze/export done at once in demo, confirm-download
   and approve-destroy order (409), two different approvers (409 on the same staff id), then keys destroyed and a
   signed demo shred certificate; retries only for `failed` jobs.
5. `CONTROL-GUIDE.md`: describe the buttons under Provisioning; drop P04 from the API-only known limit.
