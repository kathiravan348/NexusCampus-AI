# NEX-104 — Release signing: signed release manifests and offline update bundles

## Goal
A release is described by a **signed manifest** (`nexus-release/1`): version, channel, oldest version that can
upgrade straight to it, publish time, each image's content id (`sha256:…`), the heads of the product and control
migrations, the SHA-256 of the release notes, and — for an offline bundle — every file in the bundle with its
SHA-256 and size. It is signed with an Ed25519 key that never leaves OpenBao (`nexus-release`), so one signature
covers the images and every byte of the bundle. An install verifies it **offline** with pinned public keys.

- `nexus.releases`: manifest model, `sign_release`, `verify_release`, `build_bundle` (staging dir → `.tar`),
  `verify_bundle` (signature, every hash and size, no missing / extra files, no unsafe tar paths or links).
- Tools: `nexus-release-bundle` (`docker save` the images, write the manifest, sign in OpenBao, pack; `--keys`
  exports the public keys file installs pin) and `nexus-release-verify` (offline; exit code 1 on any problem).

Image signatures with cosign would need a new download; until the Owner approves one, the signed manifest pins each
image by its content id, which installs check after `docker load`.
