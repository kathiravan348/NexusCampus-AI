# NEX-106 — Tenant export (DM-8): one institution's data, encrypted so only the destination install can open it

**Status:** planned · **Owner:** — · **Branch:** task/NEX-106 · **Depends on:** NEX-112
**Requirements:** DM-8, P18, M84, M83, V-1, V-2, V-7, D58 (format), D57; import is NEX-119

## Goal
`nexus-agent export-tenant <tenant-id> --to <destination.pem>` writes one encrypted file with all of that tenant's
rows; only the destination install (holder of the import key in its OpenBao) can open it. Nothing plain on disk.

## Build
1. Vault: `create_import_key(name)` (Transit `rsa-4096`, not exportable), `public_key_pem(name)`, `rsa_decrypt(name,
   blob)`. Only the public key ever leaves OpenBao.
2. `nexus-agent import-key` (destination): creates Transit key `tenant-import` if missing, prints its public PEM.
3. `tenant_export.py` (D58 `NXTE/1`): one REPEATABLE READ snapshot as the owner role; every table with a `tenant_id`
   column, plus the tenant's own rows in the tenancy tables, filtered by that tenant id; one JSON object per row,
   streamed into the NEX-112 chunked AES-256-GCM cipher under a fresh data key. Field-encrypted values are decrypted
   with the source tenant's keys (`FieldCipher`) and carried inside the encrypted stream. Header: format, tenant id,
   source install id, schema revision, table list with row counts, the data key wrapped with RSA-OAEP-SHA256 for the
   given PEM (`cryptography`, already a dependency), the PEM's SHA-256. Refuse a PEM that is not RSA ≥ 3072 bits.
4. Job recorded in `install_backups` (`tenant_export`, running → done / failed, size); prints counts only.
5. List in the handoff exactly which columns were decrypted (from the `FieldCipher` users) and which tables exported.
