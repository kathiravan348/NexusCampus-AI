# NEX-094 — One-file language export / import for the Hindi & Tamil correction

**Status:** planned · **Owner:** — · **Branch:** task/NEX-094 · **Depends on:** NEX-071
**Requirements:** D42 (en / hi / ta), D53, D54 (Owner corrects texts before production)

## Goal
The Owner gets every user-visible text of both catalogues (institution app and Nexus Control) in one spreadsheet file
with English, the translator note, Hindi and Tamil side by side, edits Hindi / Tamil in Excel or LibreOffice, and one
command writes the corrections back. Placeholders like `{name}` are protected: a row that breaks them is refused.

## Read first
- `AGENTS.md` §6; `frontend/packages/i18n/src/{resolve.ts,keys.test.ts}`; `frontend/scripts/merge-control-texts.ts`

## Files
Create:
- `frontend/scripts/texts-export.ts` — writes `docs/review/TRANSLATIONS.csv` (UTF-8 with BOM so Excel shows Hindi and
  Tamil; columns `catalogue, key, english, note, hindi, tamil, status`)
- `frontend/scripts/texts-import.ts` — reads the edited CSV, checks each changed row (key exists, ICU valid, same
  placeholders as English), writes `messages/{hi,ta}.json` and `control/{hi,ta}.json`, prints what changed and any
  refused rows; never touches English
- `frontend/scripts/texts-csv.ts` (+ test) — CSV read/write helpers (quotes, commas, new lines)
- `docs/review/TRANSLATIONS.md` — how to correct (plain steps)
Modify:
- `frontend/package.json` (`texts:export`, `texts:import`), `docs/STRUCTURE.md`

## Acceptance checks
- [ ] Export → import with no edits changes nothing; an edited Tamil text is written; a row that drops `{name}` is
  refused with its key. `pnpm review:check` passes. `AGENTS.md` §9.

## Out of scope
- Machine translation, tenant text overrides (M04 already exports those per institution).
