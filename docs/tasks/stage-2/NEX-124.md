## Goal

mocks do, so those frozen screens work in real mode; partners see only their own accounts' deals and health.

## Build
1. `c0012_partners_analytics`: `deal_registrations` (FK partner, account), `commissions` (FK partner, invoice;
   `paid_at` set iff paid), `business_metrics` (key `month` `YYYY-MM`; ARR = 12 × MRR; new ≤ active),
   `account_health` (key `account_id`; reasons `text[]` 1–5 message keys; churn risk / score rules) — every contract
   field, checks mirroring the Zod refines. `control_app`: SELECT only on all four.
2. Export `deals`, `commissions`, `metrics`, `accountHealth`; fixtures version 9 in `export.ts` and `seed.py`; seed
   after invoices.
3. Resources: `deals` (`ctl.deal.read`; `partnerId`, `accountId`, `status`), `commissions` (`ctl.partner.read`;
   `partnerId`, `status`), `metrics` (`ctl.analytics.read`, key `month`), `account-health` (`ctl.analytics.read`;
   `churnRisk`, key `accountId`). Partner scoping by the existing `Resource` rule only: deals and health by account;
   commissions and metrics have no account, so partners see none (as the mocks).
4. Figures are stored monthly snapshots as in the mocks; nothing is computed here. Log ids only.
5. Parity: add `DealRegistration`, `Commission`, `BusinessMetrics`, `AccountHealth` to `control/parity.ts` and the map.

## Acceptance checks
- [ ] API tests per resource: list, each filter, detail and 404 match the fixtures; a role without the permission
  → 403; partner sees only its accounts' deals and health, no commissions or metrics; `control_app` cannot write;
  ARR ≠ 12 × MRR, a paid commission without `paid_at`, high churn with score ≥ 50 → refused by the database; parity green.
- [ ] `uv run --project backend backend-check` and `fnm exec --using=24 -- pnpm --dir frontend review:check` pass.
- [ ] Live: control DB migrated to c0012 and re-seeded; Control app in real mode (`control-real`): Partners (deals,
  commissions) and Analytics (metrics, account health) show the fixture rows; reset the dev data afterwards.

## Out of scope

  AI reasons, P14 trust (NEX-126), any UI change (D56).
