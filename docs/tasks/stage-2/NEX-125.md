# NEX-125 — Control: P10 access broker, Control side — a staff request becomes a signed D60 command

**Status:** planned · **Owner:** — · **Branch:** task/NEX-125 · **Depends on:** NEX-129, NEX-130 (c0016 first)
**Requirements:** P10, M83, D22, D60, V-3, V-6, V-7, D50, D56, D57; agent side is NEX-131

## Goal
Staff ask an institution for time-boxed access from Control; the request reaches the institution's own approval
screen (M83) as a signed command, and the institution's decision comes back. Control never decides access itself.

## Build
1. `c0017`: `broker_requests`, `broker_sessions`, `break_glass_cases` — every contract field, checks mirroring the
   Zod refines (decided iff not pending, M83 never in scope, two different approvers …). `control_app`: SELECT on all;
   INSERT on `broker_requests`; UPDATE (`status`, `decided_at`) on `broker_requests`; INSERT on `deployment_commands`.
2. Reads (`ctl.broker.read`, the mocks' filters / keys): `broker-requests`, `broker-sessions`, `break-glass-cases`.
3. `POST /broker-requests` (`ctl.broker.request`, body exactly as `handlers/p10.ts`): the account must be visible and
   hold the tenant; M83 in modules → 422; the tenant's deployment = the account's dedicated cell, else the shared cell
   of the account's region; none or air-gapped → 409. One transaction: insert the request (`acr-` + 16 hex, `pending`)
   and a signed command `access_request.file` for that deployment (expires in 24 h) with args `{requestId, tenantId,
   staffRef, staffDisplayName: "<name> (Nexus Support)", reason, modules, mode, durationHours}` — the documented D60
   exception (staff name and reason). 201 with the `BrokerRequest`.
4. `POST /control/api/v1/agent/access-decisions` (agent token): body `{items: [{requestId, status: approved |
   denied | expired | revoked, decidedAt}]}` (≤ 50); each must be a request whose command went to this deployment
   (else ignored and counted); first decision wins, `revoked` may follow `approved`; `expired` maps to `ended` as in the
   mocks. Answer counts only. Log ids and statuses only. A failed `access_request.file` result leaves it `pending`.
5. Parity: add `BrokerRequest`, `BrokerSession`, `BreakGlassCase` to `control/parity.ts` and the map.
