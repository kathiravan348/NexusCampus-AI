## Build
1. `c0010_support`: `tickets`, `ticket_replies` (FK ticket), `sla_policies` (key `sla_tier`), `kb_articles` — every
   contract field, checks mirroring the Zod refines (reply author rule, internal / AI-drafted only for staff, SLA
   ordering), `kb_articles` unique (locale, slug). `control_app`: SELECT on all four; INSERT on `ticket_replies`;
   UPDATE (`status`, `assignee_staff_id`, `resolved_at`) on `tickets`; nothing else.
2. Export the four collections; fixtures version 7 in `export.ts` and `seed.py`; seed after accounts.
3. `support.py`: Resources `tickets`, `ticket-replies`, `sla-policies`, `kb-articles` with `ctl.ticket.read` and the
   mocks' filters and keys. Tickets scope by `account_id` for partners; replies only through a visible ticket
   (join), never by id alone; SLA policies and articles have no account, so partners see none (NEX-113 rule).
4. `POST /tickets/{id}/replies` (`ctl.ticket.reply`, body exactly `{body, internal}`, 1–5000 chars after trim):
   404 when not visible, 409 when `closed`; status and assignee change exactly as `handlers/p09.ts`; one
   transaction; id `rep-` + random; 201 with the `TicketReply`. Log ticket id, reply id and staff id only (never body).
5. Parity: add `SupportTicket`, `TicketReply`, `SlaPolicy`, `KnowledgeArticle` to `control/parity.ts` and the map.
