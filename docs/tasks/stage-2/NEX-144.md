## Build
1. Contract `DiagnosticContentSchema` `{ id, content }` (both strings), exactly as the backend model; parity entry
   and a contract test. A fixture text per demo bundle (scrubbed, no personal data).
2. Services (M84 is L0: online only, never queued, nothing persisted): `useDiagnosticContent(id)` (enabled only while
   the modal is open), `useApproveBundle()`, `useDiscardBundle()`; on success both refetch `m84.diagnostics`.
3. Mocks: `GET /install/diagnostics/:id/content`, `POST …/approve` and `…/discard` with the backend rules: admins only
   (`m01.institution.manage`), `404` unknown id, `409` unless `ready_for_review`, `reviewedBy` = the viewer.
4. Screen: on a `ready_for_review` bundle, **Review** opens `BundleReviewModal`. It says nothing leaves the install
   until an admin approves, shows the content as read-only scrollable monospace text (wraps at 360 px), then
   **Approve sending** and **Discard** (Discard asks once more; both cannot be undone). A failed load or a 409 shows
   the error in the modal and keeps it open; success closes it with a toast. Real `<button>`s; keys `m84.bundle.*`
   with `hi` / `ta` and translator descriptions; works offline only as a clear "needs a connection" state.
5. `USER-GUIDE.md` Install & updates: the Review / Approve / Discard steps; `CONTRACTS.md` row.
