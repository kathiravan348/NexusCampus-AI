# NEX-140 — Campus app: a clear banner when the institution is frozen (`423 tenant_frozen`)

**Status:** done · **Owner:** Gemini · **Branch:** task/NEX-140 · **Depends on:** NEX-133
**Requirements:** D61, D65 (Owner OK for this Stage 1 contract and shell change), D8, D42, D15, WCAG 2.2 AA

## Goal
When the backend refuses a change because the institution is frozen (offboarding or a move), every screen shows one
persistent, plain banner explaining it, instead of only the general "save failed" message.

## Build
1. Contract: add `"tenant_frozen"` to `ApiErrorCodeSchema` with a doc line (423: the institution is frozen; reads
   still work). Mocks: `STATUS.tenant_frozen = 423` and a `MESSAGE` (the maps are typed by the code list).
2. `ApiClient` option `onTenantFrozen?: () => void`, called when a response is `423` with code `tenant_frozen` (real
   and mock mode). The services provider keeps a per-session flag (reset on sign-out or user switch) and exports
   `useTenantFrozen(): boolean`. Offline outbox: a `423` stays a fatal (not retried) write, as today.
3. `ui-core` `Banner`: generic, no domain words — props `tone` (`info` | `warning`), `title`, `children`; `role="status"`,
   tokens only, logical properties, wraps at 360 px. Story: default, warning, long text, light / dark, pseudo-locale,
   RTL. Render test.
4. Campus `Shell`: when `useTenantFrozen()` is true, show a `warning` `Banner` above the page (together with the demo
   banner in mock mode). Keys `common.tenantFrozen.title` ("This institution is frozen") and `.body` ("It is being moved
   or is leaving NexusCampus. You can still sign in and read everything, but changes are not saved."), with `hi` and
   `ta` translations and translator descriptions.
5. `USER-GUIDE.md` "When your institution leaves or moves": replace "for now the app shows its general error message"
   with the banner text; update "State as of".
