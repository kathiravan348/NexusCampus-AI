# NEX-107 — Payments (D62): Razorpay payment links for Indian invoices, signed webhook marks them paid

**Status:** done · **Owner:** Gemini · **Branch:** task/NEX-107 · **Depends on:** NEX-136 (c0020 first)

## Goal
An open INR invoice of an Indian account gets a Razorpay payment link (hosted page: no card / UPI data reaches us);
once paid, Razorpay's signed webhook marks it paid in Control exactly like a bank transfer, and Lago is told.

## Build
1. Settings (SecretStr): `NEXUS_CONTROL_RAZORPAY_KEY_ID`, `…_KEY_SECRET`, `…_WEBHOOK_SECRET`; empty = Razorpay off.
   API base is a constant (`https://api.razorpay.com/v1`), TLS verified, 10 s, no redirects; keys never logged.
2. `payments.py`: `PaymentGateway` protocol (`create_link`, `fetch_link`) and a fake. `razorpay.py`: Payment Links with
   amount = invoice total, INR, `accept_partial` false, `reference_id` = invoice id, description = invoice number,
   `expire_by` = end of the due date, `options.checkout.method` card / upi / netbanking only, `notify.email` to the
   account's `billing` contact (name + e-mail: the only personal data sent, D62).
3. `c0021`: `payment_links` (invoice FK, gateway, link id, short URL, status, created / expires; internal, in no
   contract); `payments.lago_synced` (bool). `control_app`: only the INSERT / UPDATE these steps need.
4. `POST /invoices/{id}/payment-link` (`ctl.billing.manage`): IN account, INR, `open` / `overdue` (else 409); reuses a
   live link; returns `{url, expiresAt}`. NEX-111's `invoice.created` also calls it for IN accounts; a Razorpay
   failure never blocks storing the invoice (logged by id).
5. `POST /control/api/v1/billing/razorpay-webhook`: raw body ≤ 256 KB; `X-Razorpay-Signature` = hex HMAC-SHA256 of
   the raw body with the webhook secret, constant-time (no secret or mismatch → 401, nothing stored); dedupe on
   `X-Razorpay-Event-Id`. `payment_link.paid`: link ours, amount and currency equal the invoice → one `payments` row
   (gateway `razorpay`, `gatewayRef` = payment id, its method) and the invoice paid through a helper shared with
   `record_transfer` (dunning cleared, past-due subscriptions active). `payment_link.expired` → link `expired`.
   Other events → 200, ignored. After commit: `BillingEngine.mark_paid(lago_invoice_id)`; a failure leaves
   `lago_synced` false and the billing sync retries it. Logs: ids, event, outcome only.
