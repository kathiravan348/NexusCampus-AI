# NEX-145 — Audit log: approving or discarding a support diagnostic bundle is an audit event

**Status:** planned · **Owner:** — · **Branch:** task/NEX-145 · **Depends on:** NEX-144 (same mock files)
**Requirements:** M84, M06, E-3 (every change audited), V-6, V-7; follow-up of the NEX-144 handoff

## Goal
When an institution admin approves sending or discards a support diagnostic bundle, the institution's hash-chained
audit log records who did it, to which bundle and when — not only the bundle's `reviewed_by` column.

## Build
1. `router.py` `_decide`: in the same transaction as the status update, and only when the update changed a row,
   `record_audit(auth.ctx.db, auth.ctx.tenant, AuditInput(action="m84.diagnosticBundle.approved" | "…discarded",
   actor_kind="user", actor_id=auth.ctx.user_id, target_type="diagnosticBundle", target_id=<bundle id>,
   changes=changes("status")))`. A 409 writes nothing. Bundle content, ticket text and file names never go into the
   audit event or the log (V-7).
2. Mocks: the same two actions through `appendAudit` (module `M84`, fields `["status"]`), only on success.
3. Guides: `API.md` approve / discard row — "writes an audit event"; `USER-GUIDE.md` Install & updates — the decision
   appears in **Audit & privacy**.

## Acceptance checks
- [ ] Backend test on PostgreSQL: approve → one `m84.diagnosticBundle.approved` event with the admin as actor, the
  bundle id as target and `changes = [status]`; the chain still verifies (`GET /api/v1/audit-checkpoints/verify` →
  `ok`); a second decision (409) adds no event; discard → `…discarded`; nothing from the bundle text in the event.
- [ ] Mock test: approve and discard each add one audit event; the 409 path adds none.
- [ ] `uv run --project backend backend-check` and `fnm exec --using=24 -- pnpm --dir frontend review:check` pass.
- [ ] Live: as NEX-144's live check (self-hosted mode, install folder outside the repo, Apex owner): approve one
  bundle, then **Audit & privacy** lists the event; delete the bundle, status and M84 entitlement rows afterwards.

## Out of scope
- Sending bundles (NEX-113), audit events for bundle creation by the agent (no user acts), screen changes, new texts.
