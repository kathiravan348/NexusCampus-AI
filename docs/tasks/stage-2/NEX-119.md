## Build (D59)
1. Refuse before reading any row, naming the reason (ids and revisions only): format not `NXTE/1`; `pemSha256` is
   not the SHA-256 of a version of this install's `tenant-import` public key; `revision` ≠ this database's Alembic
   revision; the tenant id already exists here; a table in the header does not exist here, or is in `NOT_EXPORTED`;
   a `vault_keys` row in the file has custody `byok` / `hyok` (checked while streaming → whole import refused).
2. Unwrap the data key with `rsa_decrypt` (OpenBao). One transaction as the owner role with
   `session_replication_role = replica`: stream rows, insert each with its columns from the row (types from
   `information_schema`; `json_populate_record` or explicit casts — say which). Commit only after the final chunk
   verified and every table's row count equals the header; otherwise roll back (nothing written).
3. Skip `audit_checkpoints` rows (signed by the source install) and count them. Load `audit_events` and
   `audit_chain_heads` unchanged.
4. After commit: for every imported `vault_keys` row with status `active` / `rotating`, create the key in this
   OpenBao (`create_key(key_name(tenant, purpose))`, idempotent). Re-encrypt every `decryptedColumns` value from the
   header with `FieldCipher` under this install's key (same `ENCRYPTED_COLUMNS` registry; none today, test it with a
   registered fake column as NEX-106 did).
5. Then, in a tenant transaction: `record_audit` action `m84.tenant.imported` (target the tenant; actor system;
   no personal data) and sign today's checkpoint (`create_checkpoint`), which re-verifies the whole imported chain.
6. Print: tenant id, tables, rows, skipped checkpoints, keys created; never people.
