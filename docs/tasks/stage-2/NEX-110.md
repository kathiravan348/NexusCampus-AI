## Build
1. V-tests for Control (each names its V id): no Control route or tool connects to a product database; Control
   tables hold no institution personal data beyond the documented account contacts and D60 exceptions (schema walk);
   every Control route is either agent-token, webhook-signature or staff-session + permission guarded (route walk, as
   Stage 1); partner scoping on every list; logs carry ids only (capture during the API tests).
2. Command channel: forged, replayed, expired, foreign-deployment and unknown-kind commands never run; a stolen agent
   token cannot read another deployment's commands or post their results; air-gapped installs make no request.
3. Request safety for staff writes: the session cookie is `HttpOnly`, `Secure` in prod, `SameSite=Strict`; every
   Control write also checks `Origin` against `NEXUS_CONTROL_APP_PUBLIC_URL` (403 otherwise); security headers
   (`Content-Security-Policy` for the API, `X-Content-Type-Options`, `Referrer-Policy`, HSTS in prod).
4. Key custody: the product install's OpenBao policy denies `transit/export/*` and keeps only what crypto-shred
   needs; both install scripts revoke the OpenBao root token after setup (recreate it with the unseal key only when
   an operator needs it; README says how).
5. Control response models enforce the frozen contracts' cross-field rules (e.g. `resolvedAt` iff resolved), so the
   parity tests also reject what Zod rejects; list any rule left to the database with a reason.
6. `docs/review/STAGE-2-SECURITY.md`: each V-rule and follow-up with its test or change, and open items.
