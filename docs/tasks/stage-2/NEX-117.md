# NEX-117 — M84 online update check, signed end to end (Control stores the signed manifest; the agent verifies it)

**Status:** done · **Owner:** Gemini · **Branch:** task/NEX-117 · **Depends on:** NEX-115, NEX-116

## Goal
Control stores each signed release manifest; an install with telemetry on asks `GET /agent/update` and shows an
online `UpdateOffer` only after verifying that manifest with its pinned release keys.

## Build
1. `c0008`: `releases.signed_manifest` text, nullable, internal (never in `Release`); check `signed_manifest IS NULL
   OR signed`; `control_app` keeps SELECT only.
2. `nexus-control-release-import <file.release.json>` (owner connection): verify it with OpenBao key `nexus-release`'s
   public keys, match the row by channel + version + `minUpgradeFrom`, store the raw text, set `signed = true`;
   refuse (exit 1, a reason) a bad / unknown signature, no matching row, a mismatch or a `withdrawn` release.
3. `GET /agent/update` answers `{"release": Release | null, "manifest": <stored signed file as JSON> | null}` and
   never offers a release without a stored manifest. Health check-in and the other NEX-115 rules unchanged.
4. In `health.py`, make the URL rule one public helper (`control_endpoint(base, path)`: https only, plain http only to
   this machine, query and fragment dropped) used by health reports and `online.py`.
5. `online.py` — `check_online(settings, keys, current, support_ends, transport=None)`: skipped (no call) when
   air-gapped, telemetry off or no token; GET with Bearer token, TLS verified, 10 s, no redirects. Accept an offer only
   if `verify_release(…, raw_manifest=…)` passes with the pinned `release-keys.json`, manifest version / channel /
   `minUpgradeFrom` equal the release's, it is newer than `current` and allows upgrading from it (`version_key`).
   Offer = `{version, channel, source: "online", signatureValid: true, securityFix (manifest), releaseNotes
   (migrationNotes, ≤ 5000), coveredBySupport}`. Any failure → no offer and a one-line reason; never raises.
6. `state.run_once` takes the online result as an argument: a verified offline bundle wins; else the online offer.
   `last_update_check_at` = now only after a real online call (air-gapped stays NULL); `run.py` runs the check before
   the transaction and prints its one line.
