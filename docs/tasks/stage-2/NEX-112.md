# NEX-112 — M84 encrypted backups and support diagnostic bundles

**Status:** done · **Owner:** Claude · **Branch:** task/NEX-112 · **Depends on:** NEX-105
**Requirements:** M84, DM-8, V-6 (nothing leaves until a person approves), V-7, D23, D55

## Goal
- **Encrypted backups** (`nexus-agent backup`): every table streamed with PostgreSQL `COPY … (FORMAT BINARY)` straight
  into AES-256-GCM encryption (1 MB chunks, nonce = file prefix + counter, chunk index and "last chunk" bound into each
  tag, so truncation, reordering and edits are detected). A fresh 256-bit data key per backup from OpenBao Transit
  (`install-backup`); only the wrapped key is stored in the file header. Plain data never touches the disk. The job is
  recorded (`BackupJob`: running → done / failed, size) and `lastBackupAt` updated. No `pg_dump` (would be a new
  download); runs with the owner connection (a backup must read every tenant).
- **Restore** (`nexus-agent restore <file> --into <empty database URL>`): unwraps the key, verifies every chunk while
  streaming, refuses a file whose schema revision differs, builds the schema with the migrations and loads each table.
- **Diagnostic bundles** (`nexus-agent diagnostics [--ticket TCK-…]`): versions, migration heads, install status,
  agent settings without secrets, and log lines with e-mail addresses, phone numbers, tokens, IP addresses and long
  numbers removed. Saved as `ready_for_review`; an admin reads the content and approves or discards it
  (`GET /install/diagnostics/{id}/content`, `POST …/approve`, `POST …/discard`). Nothing is sent (sending is NEX-113).
- `GET /install/backups` and `/install/diagnostics` list the real jobs and bundles.
