## Goal
Control can queue a signed command for one deployment; that deployment's agent fetches it with its own token and
reports a result. Control never connects to a deployment. Only kind `ping` exists in this task.

## Build
1. `commands/format.py` (shared with the agent): `nexus-command/1` = canonical JSON `{format, id, deploymentId,
   tenantId|null, kind, args, issuedAt, expiresAt, issuedBy}`; `sign_command(vault, key, cmd)` (Transit Ed25519 key
   `nexus-command`, never exported; the payload names the key version) and `verify_command(raw, signature, keys,
   now)` (pinned public keys; refuses a bad signature, unknown key, wrong format, expired, `expiresAt - issuedAt`
   over 24 h). `args` ≤ 2 KB of ids and enums only — never personal data.
2. `c0015`: `deployment_commands` (id `cmd-` + 16 hex, deployment FK, tenant id, kind, signed payload text,
   signature, status `pending` / `delivered` / `done` / `failed` / `rejected` / `expired`, issued / delivered /
   finished times, result `jsonb` ≤ 4 KB). `control_app`: SELECT and UPDATE (status, times, result) only — commands
   are inserted only by the owner tool in this task.
3. `GET /control/api/v1/agent/commands` (agent token via `agent_deployment`): that deployment's unexpired `pending`
   and `delivered` commands (max 20, oldest first) as `{items: [{command, signature}]}`; marks `pending` →
   `delivered`; past-expiry rows → `expired`. Air-gapped → 403; max 1 request per 30 s per deployment → 429.
4. `POST /control/api/v1/agent/commands/{id}/result` (agent token): body `{status: done|failed|rejected,
   result: object ≤ 4 KB}`; only the deployment's own command (else 404), only once (else 409). Log ids, kind, status.
5. `nexus-control-command ping <deployment-id>` (owner role, like `devtools/agent_token.py`): signs and queues a `ping`
   (expires in 10 min) and prints the command id only. Control allows kind `ping` only; later tasks add theirs.
