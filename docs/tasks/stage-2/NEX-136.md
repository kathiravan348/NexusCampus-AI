# NEX-136 — Control: P18 moves for real (D61) — a portability job walks the seven steps

**Status:** done · **Owner:** Gemini · **Branch:** task/NEX-136 · **Depends on:** NEX-135, NEX-134 (c0019 first)

## Goal
Staff move one tenant between regions or between SaaS and self-hosted with a portability job. Steps on our cells
run as signed commands; steps on a customer's install (or carrying the file) are confirmed by staff. Control never
holds the export file.

## Build
1. `c0020`: `control_app` INSERT / UPDATE (`steps`, `status`) on `portability_jobs`; UPDATE (`region`, `tenant_ids`,
   `delivery_model`) on `accounts`; internal columns: source / destination deployment, PEM fingerprint, file name,
   expected rows, offboarding job id.
2. `POST /portability-jobs` (`ctl.portability.manage`):
   `{accountId, tenantId, direction, toRegion}`; resolves source and destination (cells by region, the account's
   self-hosted deployment); a region move needs two regions (422); 201 with all seven steps `pending`.
3. Steps: `preflight` — destination cell: `tenant.import_key`; self-hosted destination: staff upload the install's
   PEM (`…/confirm` with `{pem}`). `export_encrypted` — source cell: `tenant.freeze` then `tenant.export` for that PEM;
   self-hosted source: staff confirm with `{fileName, rows}`. `transfer` — staff confirm the file is in the
   destination's import folder. `import` + `verify` — destination cell: `tenant.import` (both steps from its result,
   `chainOk` and `checkpointOk` must be true); self-hosted: staff confirm with the counts. `cutover` — staff confirm;
   the account's region / delivery model / tenant ids change in one transaction. `shred_source` — starts a NEX-134
   offboarding job for the source copy; done when its certificate is issued.
4. `POST /portability-jobs/{id}/confirm` (`{step, …}`): only the current step, only when it is a staff step (else
   409); `failed` jobs can be retried from the failed step (`…/retry`).
5. Log job id, step, staff id, outcome; never the PEM or file contents.
