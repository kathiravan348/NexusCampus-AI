# NEX-108 — Packaging: Nexus Control as a Compose stack (control backend, staff realm, billing), images only

**Status:** planned · **Owner:** — · **Branch:** task/NEX-108 · **Depends on:** NEX-111
**Requirements:** DM-9, P13, D51, V-1, V-6, D57; Helm is NEX-120 (needs the Owner's OK to download `helm`)

## Goal
Our provider plane runs from one Compose file with only already-downloaded images: control database, control backend
(the existing `nexuscampus-api` image, another command), Keycloak with the staff realm, Valkey, OpenBao and the Lago
stack — internal network only, one port published (the control backend, 127.0.0.1).

## Build
1. Services: `control-db` (postgres, same image as product), `control-migrate` (control Alembic + seed only when
   `NEXUS_CONTROL_DEMO=1`), `control-api` (`uvicorn --factory nexus.control.main:app`, 0.0.0.0:8100 inside, published
   127.0.0.1:8100), `staff-keycloak` (staff realm imported at start, MFA required as in dev), `valkey`, `openbao`,
   and the Lago services from `backend/compose.billing.yaml` (`include:`, no duplication). Same image tags / digests
   as today; no new image.
2. Secrets only from `.env` (never committed; `.env.example` lists names with empty values); the install script
   creates random secrets once (no echo), the OpenBao keys (`nexus-licence`, `nexus-release`) and the Lago org key.
3. Health checks and `depends_on` order like the product stack; memory limits; `restart: unless-stopped`; read-only
   root file system where the image allows.
4. README: install, upgrade (migrate runs first), backup of control-db and Lago-db, where the keys live, rotation.
