## Goal
A SaaS cell's agent runs a signed `tenant.provision` command: it creates the institution with the five contract steps
(`create_tenant`, `create_keys`, `apply_profile`, `seed`, `invite_owner`), safely re-runnable, and reports which
steps are done. Until now tenants only came from demo seed data.

## Build
1. `provision_tenant(settings, vault, keycloak, args) -> StepReport`. Args (strict): `tenantId` (given by Control),
   `name` (the institution's name), `institutionType`, `region` (must equal this cell's region), `planCode` (must
   exist in `plans`), `trialDays|null`, `owner: {legalName, workEmail}` — the documented D60 exception.
2. Steps, each idempotent (re-running a done step changes nothing): `create_tenant` (owner role: `tenants` row +
   first `institutions` row of that type) → `create_keys` (`provision_key` for `tenant_data`) → `apply_profile`
   (type profile + `tenant_plans` / `entitlements` from the plan's modules) → `seed` (the system roles and default
   preferences every tenant starts with — no people; list them in the handoff) → `invite_owner` (Keycloak
   organization for the tenant + the owner invited through `invite`, with the institution-owner role).
3. Each step records an M06 audit event in the tenant (actor system, no personal data in `changes`). Stop at the
   first failing step; report `{tenantId, stepsDone: [...], failedStep?, reason?}` (reason = a code, never text from
   an exception).
4. Agent kind `tenant.provision`: only when `install_mode` is `saas` (a cell); a self-hosted install → `rejected`.
5. The owner's e-mail and name are never logged or printed; output prints the tenant id and step names only.
