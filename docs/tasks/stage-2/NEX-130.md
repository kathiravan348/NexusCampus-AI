## Goal
Staff with `ctl.release.manage` publish a draft release only when its signed manifest verifies, and start a rollout
ring only after the earlier rings are done. Installs then see the offer through the existing update check (NEX-115).

## Build
1. `c0016`: `control_app` gets UPDATE (`status`, `signed`, `published_at`) on `releases` and UPDATE (`status`,
   `started_at`) on `rollouts`; nothing else.
2. `POST /releases/{id}/publish` (`ctl.release.manage`, body exactly `{notesReviewed?: boolean}`): 404 unknown,
   409 unless `draft`; AI-drafted notes need `notesReviewed: true` (422 with the mocks' message); the stored
   `signed_manifest` must exist and verify with the `nexus-release` public keys from OpenBao and name this release's
   version and channel (else 409 "not signed"). Sets `published`, `signed = true`, `published_at`; returns `Release`.
3. `POST /rollouts/{id}/start` (`ctl.release.manage`, no body): 404 unknown; 409 unless the release is `published`,
   the rollout is `pending` and every earlier ring of the release is `done`. Sets `running` + `started_at` (real
   installs move themselves; the mock's instant `done` is demo only). Returns `Rollout`.
4. In `POST /agent/health` (fleet): after storing a check-in, a `running` rollout whose listed deployments all report
   that release's version (or newer) becomes `done`. One transaction; log ids only.
5. Both writes in one transaction with the row locked; log staff id, release / rollout id and outcome.
