# NEX-064 — Images and self-hosted Compose install

**Status:** planned · **Owner:** — · **Branch:** task/NEX-064 · **Depends on:** NEX-063
**Requirements:** PLAN Stage 1 exit, ARCHITECTURE §9 (same images everywhere), D45, D46

## Goal
One set of container images (api, worker, web) runs both as a SaaS region cell and as a self-hosted Docker Compose
install with Keycloak, Vault (or OpenBao), PostgreSQL 16 + pgvector and Redis; a fresh machine installs Stage 1 with
one documented command and a seed of demo or empty data.

## Read first
- `AGENTS.md` (§5a Docker rules); `docs/ARCHITECTURE.md` §9; `backend/compose.yaml`

## Files
Create:
- `backend/Dockerfile` (multi-stage, non-root, Python 3.12 slim, uv sync --frozen), `frontend/apps/campus/Dockerfile`
  (build + static server with SPA fallback and service worker headers)
- `deploy/compose/compose.yaml`, `deploy/compose/.env.example`, `deploy/compose/README.md` (install, upgrade with
  forward-only migrations, backup / restore of PostgreSQL and Vault, uninstall)
- `deploy/compose/scripts/install.ps1` and `install.sh` (same steps; print `[timing] compose:up …`)
Modify:
- `docs/STRUCTURE.md`, `docs/TIMINGS.md` (`compose:up` baseline), `docs/guides/USER-GUIDE.md` (install section)

## Build
1. All ports on `127.0.0.1` by default; a reverse-proxy note for real hostnames (TLS terminates there).
2. Every service has `mem_limit`, healthcheck and a named volume; images pinned by digest in the example.
3. Secrets only from `.env` / Vault; the example file has placeholders, never values.

## Acceptance checks
- [ ] On a clean Docker host: install script → app reachable, sign-in through Keycloak, demo seed visible.
- [ ] Upgrade path tested once (rebuild images, run migrations, data kept).
- [ ] Definition of done in `AGENTS.md` §9; `docker compose down` when done.
