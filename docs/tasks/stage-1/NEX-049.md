# NEX-049 — SSO providers and SCIM 2.0 (M02)

**Status:** planned · **Owner:** — · **Branch:** task/NEX-049 · **Depends on:** NEX-048
**Requirements:** M02, ARCHITECTURE §8, D44

## Goal
An institution admin configures an OIDC or SAML provider (stored in NexusCampus and created as a Keycloak identity
provider linked to the tenant's organization by email domain), and an external directory provisions users through
SCIM 2.0 `/scim/v2/Users`.

## Read first
- `AGENTS.md`; `docs/DECISIONS.md` D44; `frontend/packages/contracts/src/user.ts` (SsoProvider)
- `docs/guides/API.md` (M02 SSO rows); `frontend/packages/mocks/src/handlers/m02.ts` (SSO cases)

## Files
Create (`backend/`):
- `src/nexus/modules/m02/sso.py` (CRUD = contract; https issuer only; domains lower-case unique; client secret only
  written to Vault, never returned), `scim.py` (Users: list/filter `userName eq`, get, create, patch active, delete =
  suspend; bearer token per tenant, hashed), `migrations/versions/0005_sso_scim.py`
- `tests/m02/test_sso.py`, `tests/m02/test_scim.py` (SCIM core schema fixtures)
Modify:
- `backend/src/nexus/modules/m02/keycloak_admin.py`, `docs/guides/API.md`, `docs/guides/DATABASE.md`

## Build
1. `http://` issuer → `400 invalid_request` (same detail path as the mock).
2. SCIM errors use the SCIM error schema; everything else uses the NexusCampus envelope.
3. Every change audits (`m02.sso.updated`, `m02.scim.userProvisioned`, …).

## Acceptance checks
- [ ] Saving a provider updates in place (no duplicate) and creates/updates the Keycloak IdP (admin client mocked).
- [ ] SCIM create → user `invited`; patch `active=false` → `suspended`; wrong token → 401.
- [ ] No response or log ever contains a client secret or SCIM token.
- [ ] Definition of done in `AGENTS.md` §9.

## Out of scope
- SCIM Groups; just-in-time provisioning rules beyond domain match.
