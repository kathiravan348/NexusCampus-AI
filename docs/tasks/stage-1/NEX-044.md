# NEX-044 — Audit core: append-only hash-chained audit writer and domain event outbox

**Status:** done · **Owner:** Claude · **Branch:** task/NEX-044 · **Depends on:** NEX-043
**Requirements:** M06, ARCHITECTURE §6 (Audit, events), D25, V-3

## Goal
Any module can write an audit event and a domain event in the same transaction as its change; audit rows are
append-only, hash-chained per tenant (same hash input as the mocks) and verifiable.

## Read first
- `AGENTS.md`; `docs/ARCHITECTURE.md` §6; `frontend/packages/contracts/src/compliance.ts` (AuditEvent), `event.ts`
- `frontend/packages/mocks/src/fixtures/audit.ts` (`auditHashInput`)

## Files
Create (`backend/`):
- `migrations/versions/0002_audit_outbox.py` — `audit_events` (RLS; `REVOKE UPDATE, DELETE` from `nexus_app`),
  `domain_events_outbox` (RLS), per-tenant chain head
- `src/nexus/core/audit.py` (`record_audit(session, …)`; changed **field names only**; `grantId` iff provider grant)
- `src/nexus/core/events.py` (`emit_event(session, event)`; envelope = `event.ts`)
- `src/nexus/core/hashchain.py` (`sha256(id|occurredAt|action|prevHash)`, exactly `auditHashInput`;
  `verify_chain(tenant_id, from, to)` → first broken row or OK)
- `tests/test_audit_chain.py`, `tests/test_outbox.py`
Modify:
- `backend/src/nexus/seed/demo.py` (load mock audit rows), `docs/guides/DATABASE.md`

## Build
1. Lock the tenant's chain head `FOR UPDATE` so concurrent writers never fork the chain.
2. The hash covers ids and metadata only, so crypto-shredding never breaks it (ARCHITECTURE §6).
3. Seeded mock audit rows keep their stored hashes, and those verify.
