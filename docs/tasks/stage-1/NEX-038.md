# NEX-038 — PWA and MSW share one service worker in mock builds (fix for NEX-030, found by NEX-021)

**Status:** done · **Owner:** Claude · **Branch:** task/NEX-038 · **Depends on:** NEX-030
**Requirements:** O-1–O-3, D36

## Goal
A mock-mode production build (`VITE_DATA_MODE=mock vite build`, used by `review:start` and e2e) has one service worker
that both serves the precached app shell offline and answers the mock API, so the app never flips between
`mockServiceWorker.js` and `sw.js`, never shows a false "new version" notice, and opens offline.

## Found by
NEX-021 probe on a mock build: load 1 → MSW active, `sw.js` waiting ("new version" notice); load 2 → blank page;
load 3 → same as 1. Both workers claim scope `/`, so only one can control the page.

## Files
Create:
- `frontend/apps/campus/src/sw/sw.ts` — Workbox `injectManifest` worker: precache + clean-up, navigation fallback
  `/index.html` (deny `/api/`), `SKIP_WAITING` message for the prompt flow; in mock builds imports
  `/mockServiceWorker.js` after the Workbox routes and lets MSW see only requests the precache does not answer
- `frontend/apps/campus/src/sw/tsconfig.json` — WebWorker lib for the worker only (kept out of the DOM build)
Modify:
- `frontend/apps/campus/vite.config.ts` — `strategies: "injectManifest"`, `srcDir`/`filename`, same globs/ignores
- `frontend/apps/campus/src/main.tsx` — MSW `worker.start({ serviceWorker: { url } })`: `/sw.js` in production mock
  builds, `/mockServiceWorker.js` in dev
- `frontend/apps/campus/package.json` (`workbox-precaching`, `workbox-routing` 7.4.1, `typecheck` also checks
  the worker), `frontend/apps/campus/tsconfig.json` (exclude `src/sw`), `docs/STRUCTURE.md`
