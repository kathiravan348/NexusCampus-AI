# NEX-030 — PWA: manifest, service worker (Workbox), offline app shell, install and update prompts

**Status:** planned · **Owner:** — · **Branch:** task/NEX-030 · **Depends on:** NEX-012, NEX-035
**Requirements:** D13, D17, O-1, O-3, O-4, G-1, G-8, D36

## Goal
`apps/campus` is an installable PWA: the app shell and static assets load offline after the first visit, users can
install it, and a new version is offered with a non-blocking "update available" toast. MSW keeps working in mock mode.

## Files
Create (in `frontend/apps/campus/`):
- `src/pwa/registerPwa.ts` (+ test) — wraps `virtual:pwa-register` (`registerSW({ onNeedRefresh, onOfflineReady })`);
  exposes `usePwaUpdate()` → `{ needRefresh, offlineReady, update() }`
- `src/pwa/InstallPrompt.tsx` (+ test) — listens for `beforeinstallprompt`, shows an install button in the shell header
  only when available; hides after install (`appinstalled`); no fake button
- `src/pwa/UpdateToast.tsx` (+ test) — toast "new version available" with **Reload** action; "ready to work offline"

  in mock mode the MSW worker script stays excluded from precache
- `src/app/ShellHeader.tsx` (mount `InstallPrompt`), `src/App.tsx` (mount `UpdateToast`)

## Build
1. API responses are never cached by the service worker: L1 data lives in the encrypted `@nexus/offline` cache (O-3).
2. Tests mock `virtual:pwa-register` and the `beforeinstallprompt` event. Build output contains `manifest.webmanifest`
   and `sw.js` (assert in a small Vitest that reads `dist/` only if present, else skip — or check in handoff).
3. Manual check (handoff): `pnpm build` + `pnpm preview`, load once, go offline in DevTools, reload → shell renders
   with the offline `SyncStatus`; Lighthouse PWA installable.

## Acceptance checks
- [ ] Offline reload of a visited app shows the shell, not the browser error page; `/api` is not in the SW cache.
- [ ] Install button appears only when the browser offers it; update toast reloads into the new version.
- [ ] `pnpm review:check` passes; USER-GUIDE updated; Definition of done in `AGENTS.md` §9.
