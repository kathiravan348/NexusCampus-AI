# NEX-017 — Audit, privacy & consent (M06): audit viewer, consent records, data requests, compliance pack

**Status:** planned · **Owner:** — · **Branch:** task/NEX-017 · **Depends on:** NEX-012
**Requirements:** M06 (L0), E-3, G-6, A-3, D22, D25

## Goal
An admin (or group auditor) browses the tamper-evident audit log with filters and a chain-integrity check, sees
consent records per person and purpose, manages data subject requests through their statuses with due dates, and
sees which compliance pack(s) apply to the institution.

## Files
Create (in `frontend/apps/campus/src/modules/m06/`), each with a `*.test.tsx`:
- `PrivacyPage.tsx` (Tabs: Audit log · Consents · Data requests · Compliance)
- `AuditTab.tsx` (`DataTable` paged from the API: time in tenant zone, actor, action, target, device; filters action /
  actor / date range; detail `Modal` lists changed field names with "sensitive" badge — never values; provider-grant
  events highlighted with the grant id), `ChainCheck.tsx` (button: verifies `prevHash` links of the loaded page and
  reports intact / broken at row n — client-side, labelled "page check")
- `ConsentsTab.tsx` (filter by purpose/status; person name (masked per API), purpose, status, given by guardian,
  method, dates)
- `DataRequestsTab.tsx` (list with kind, status, due date, overdue badge; detail with status actions: start →
  complete / reject with reason)
- `ComplianceTab.tsx` (packs: DSR due days, minor age threshold, guardian consent for AI/media, default retention)
Create (services): `frontend/packages/services/src/modules/m06.ts` (+ test) — `useAuditEvents(filters, page)`,
`useConsents`, `useDataRequests`, `useCompliancePacks`, `useUpdateDataRequest`
Modify:
- `frontend/packages/mocks/src/handlers/m06.ts` (+ test) — `PATCH /data-requests/:id` (allowed transitions only:
  received → in_progress → completed | rejected; else 409; permission `m06.dsr.manage`; audit event appended to the
  chain)
- `frontend/packages/services/src/index.ts`, `app/modules.ts` (one line `M06`, `/privacy`, `ShieldCheck`,

## Build
1. L0: offline shows the shell's offline notice; no cached audit data on device.
2. Dates via `@nexus/i18n` formatters in tenant time zone; overdue = `dueAt` < now (inject `now` for tests).
3. Tests: filter by action narrows rows; detail shows field names only; chain check intact on fixtures and broken when
   a test tampers one hash; DSR transition updates status and adds an audit row; invalid transition shows error toast.
