# NEX-229 — M32 Homework & assignments screens (list, assignment view, learner submit offline L2)

**Status:** planned · **Owner:** — · **Branch:** task/NEX-229 · **Depends on:** NEX-223, NEX-228 (same i18n files)

## Goal
Demo campus app "Assignments" screen: assignments per course space, an assignment view, and a learner can save a
draft and submit text or an https link offline (L2); staff see submission statuses only.

## Build
1. `modules.ts`: `M32`, path `teaching/assignments`, icon `ClipboardPen` (lucide), permission `m32.assignment.read`,
   `L2`, keys `m32.nav.title` / `m32.nav.summary`, lazy `../modules/m32/AssignmentsPage`.
2. `AssignmentsPage`: heading, intro, `LastSynced`; `useAssignments()` list (title, due date, status text + icon,
   "Group work" / "Peer review" labels); status filter; selecting one shows `AssignmentView` (back link, 360 px).
3. `AssignmentView`: instructions as escaped plain text (no HTML / markdown), open / due / late-until times, max
   marks or "Feedback only", allowed kinds; learner → `SubmissionForm`; staff → `SubmissionList`.
4. `SubmissionForm` (learner, own latest submission from `useAssignmentSubmissions(id)`): text area and https link
   field only for kinds the assignment allows; file / audio / photo kinds show "Upload comes later" (no upload);
   "Save draft" and "Submit"; after the due date shows "Late" before submitting; after `lateUntil` or when the
   assignment is closed the form is read-only with the reason. Returned / resubmission-requested shows the status.
5. Write `POST /assignments/:id/submissions` (learner of a course space that has the assignment, `m32.assignment.read`):
   body `{ clientId, text, linkUrl, submit }` strict; upserts the viewer's own latest draft (same `clientId` →
   same row, idempotent); `submit: true` sets `submitted` (or `late` after `dueAt`) and `submittedAt`; empty answer on
   submit → 400 `invalid_request`; after `lateUntil` / closed / not published → 409 `conflict`; staff or another
   tenant / not enrolled → 404; parses with `AssignmentSubmissionSchema`; error details never contain answer text.
6. `SubmissionList` (staff who manage or teach the space): learner name, status text + icon, attempt, submitted
   time; never answer text; no marking controls.
7. Hook `useSaveSubmission()` via `useOutboxMutation` (`moduleId: "M32"`, `clientId` as idempotency key, same options
   as the m29 submit hook), invalidating the submissions query; offline the form says "Queued — will send when
   online" (L2). Answer text never goes to logs, telemetry or error messages (V-7).
8. i18n en / hi / ta (D42); tokens only; files ≤ 300 lines; tests use `await screen.findBy…` after render.
