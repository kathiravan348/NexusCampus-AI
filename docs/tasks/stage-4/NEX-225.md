permissions, survey anonymity and result suppression, and credential privacy; `@nexus/services` has typed hooks.

## Build
1. `fixtures/index.ts`: export `surveys`, `credentials`, `ids-stage4-engage`. `db.ts`: a collection per array; no
   `DEMO_FIXTURES_VERSION` bump (if needed: a question).
2. Handlers: GET only, `get()` from `route.ts`, `list()` pages, `ofTenant` always, `entitled()` per module, 404 for
   another tenant's id or a row the viewer may not see; files ≤ 300 lines; no personal data, titles or answers in errors.
   M44 (`m44.survey.read`): `/surveys`, `/surveys/:id` — `m44.survey.manage` sees the whole tenant; others only
   `open` / `closed` surveys whose `audience` matches their role (learner → learners, guardian → guardians, staff →
   staff). `/surveys/:id/results` and `/surveys/:id/themes` need `m44.results.read`: results below
   `minResponsesToShow` come back suppressed exactly as the fixture holds them (never recomputed from responses); a
   faculty survey's results and themes only for the profiles in `FACULTY_RESULT_VIEWER_PROFILE_IDS[surveyId]`, else
   404. No endpoint returns `SURVEY_RESPONSES` (individual responses are out of scope; G-6, V-7).
   M45 (`m45.credential.read`): `/credential-templates`; `/issued-credentials` — `m45.credential.issue` sees the whole
   tenant; a learner only own rows (hidden ones too); a guardian only own minor learners' rows that are not in
   `HIDDEN_CREDENTIAL_IDS`; other staff none; `/issued-credentials/:id` same rules. Public
   `/credential-verifications/:code` (no session, no tenant): the fixture row for a known code, else the same shape
   with `result: "not_found"` and nulls — status 200 for both, no learner data, no ids.
3. Services: one `useX()` hook per endpoint (pattern of `modules/m43.ts`, keys in `keys.ts`), exported from `index.ts`;
   `useCredentialVerification(code)` disabled for an empty code.
