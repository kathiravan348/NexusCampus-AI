# NEX-267 — MSW handlers + services: M42, M43 — higher-ed academics, academy store (read)

## Goal
Demo mode serves the NEX-263 M42 and M43 data through MSW read endpoints with tenant isolation and deny-by-default
permissions, and `@nexus/services` has typed hooks for them. Card data never exists; buyer and payout e-mails are
served only to people allowed to see orders / manage the store.

## Build
1. `fixtures/index.ts`: export `higher-ed`, `store`, `ids-stage4-store`. `db.ts`: a collection per array; no
   `DEMO_FIXTURES_VERSION` bump (if needed: a question).
2. Handlers: GET only, `get()` from `route.ts`, `list()` pages, `ofTenant` always, `entitled()` per module (M42: he,
   voc; M43: tp), 404 for another tenant's id; `?learnerId=` of another tenant → 404; files ≤ 300 lines; no personal
   data, e-mails or titles in errors.
   M42 (staff only): `m42.registration.read` → `/program-requirements`, `/registration-windows`,
   `/elective-registrations?learnerId=&windowId=`; `m42.audit.read` → `/degree-audits?learnerId=`,
   `/theses?learnerId=`, `/path-advice?learnerId=` (path advice with status `draft` only with
   `m42.registration.decide`, else `reviewed` rows only — A-4).
   M43 (staff only): `m43.store.read` → `/store-products`, `/store-products/:id`, `/coupons`;
   `m43.order.read` → `/store-orders`, `/store-orders/:id`, `/store-subscriptions`;
   `m43.store.manage` → `/affiliates`, `/affiliate-conversions` (payout e-mail and commission are manager-only).
   Learners and guardians have no M42 / M43 grant → 403 (family and buyer views come later).
3. Services: one `useX()` hook per endpoint (pattern of `modules/m41.ts`, keys in `keys.ts`), exported from `index.ts`.
