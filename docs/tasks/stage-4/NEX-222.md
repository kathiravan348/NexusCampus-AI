# NEX-222 — MSW handlers + services: M29, M30, M31; merge Stage 4 access into the mock database

## Goal
Demo mode serves the NEX-220 data through MSW read endpoints with tenant isolation, deny-by-default permissions and
draft / hidden-row filtering, and `@nexus/services` has typed hooks for them — ready for the M29–M31 screens.

## Build
1. `db.ts`: merge `stage4AccessFixtures()` the way Stage 3 access is merged — permissions appended, each system role
   gets its `STAGE4_ROLE_PERMISSIONS`, entitlements include `STAGE4_ENTITLEMENTS`; new collections for every NEX-220
   set. Do not edit `stage4-access.ts`, `rbac.ts`, `plans.ts`, `export.ts` or `backend/`.
2. Handlers: GET only, `get()` from `route.ts`, `list()` pages, `ofTenant` always, `entitled()` per module, 404 for
   another tenant's id. M29 `/outcome-frameworks`, `/outcomes?frameworkId=`, `/outcome-mappings?frameworkId=`,
   `/syllabus-units?subjectId=`, `/lesson-plans?subjectOfferingId=`, `/syllabus-coverage?subjectOfferingId=` (computed
   `SyllabusCoverage` + entries) — `m29.curriculum.read`; lesson plans need `m29.lessonplan.write` or
   `m29.lessonplan.review`. M30 `/course-spaces`, `/course-spaces/:id`, `/course-spaces/:id/modules`,
   `/course-spaces/:id/items`, `/course-spaces/:id/progress`, `/course-spaces/:id/threads`, `/threads/:id/posts` —
   `m30.course.read`; without `m30.course.manage` only published spaces where the viewer is staff or a learner of a
   listed class group, only published items, and progress only the viewer's own row (staff of the space see all);
   hidden posts only with `m30.discussion.moderate`. M31 `/content-items`, `/content-items/:id`, `/content-assets`,
   `/content-attempts?contentItemId=` — `m31.content.read`; draft / in-review items and assets only with
   `m31.content.manage`; attempts: own rows, all with `m31.content.manage`. Assets are metadata only (D87 rule 4).
3. Services: one `useX()` hook per endpoint (pattern of `modules/m15.ts`, keys in `keys.ts`), exported from `index.ts`.
4. Files ≤ 300 lines (split a handler into `mNNStore.ts` like `m02Store.ts` if needed); no personal data in errors or logs.
