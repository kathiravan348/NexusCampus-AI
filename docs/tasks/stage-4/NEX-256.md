# NEX-256 — Contracts (M33): negative marking — item penalties and signed scores

**Status:** done · **Owner:** Claude · **Branch:** task/NEX-256 · **Depends on:** NEX-247, NEX-218
**Requirements:** M33, M40, D87 (review follow-up of NEX-218)

## Goal
M33 can run entrance-style tests with negative marking (+4 / −1 in JEE and NEET, −1/3 and −2/3 in GATE): items carry a
penalty that learners see before answering, and response and attempt scores may go below zero, as M40 ranks already do.

- `AGENTS.md` §7–§9; `docs/CONTRACTS.md` (`questions.ts`, `online-tests.ts`, `test-prep.ts` rows)
- `frontend/packages/contracts/src/{questions,online-tests,test-prep}.ts` and their tests

## Files
Modify in `frontend/packages/contracts/src/`: `questions.ts`, `questions.test.ts`, `online-tests.ts`,
`online-tests.test.ts`. Modify `docs/CONTRACTS.md` (the two M33 rows).

## Build
1. `QuestionItemSchema` gains `negativePoints` (number 0…`maxPoints`, 0.01 steps; 0 = no penalty); `essay` and
   `order` items always have 0 (manual or partial marking only). `QuestionDeliverySchema` gains the same field so a
   learner sees the penalty before answering.
2. `TestResponseSchema`: `autoScore` and `manualScore` become signed numbers in 0.01 steps (the server keeps each between
   −penalty and the item's points); `manualScore` keeps its marker rule.
3. `TestAttemptSchema`: `scorePoints` becomes a signed number in 0.01 steps between −`maxPoints` and `maxPoints`;
   `maxPoints` stays positive. The existing status ↔ score rules stay.
4. Update the doc comments (server: a response's score lies between −the item's penalty and its points; an unanswered
   item scores 0) and the two `CONTRACTS.md` rows.
