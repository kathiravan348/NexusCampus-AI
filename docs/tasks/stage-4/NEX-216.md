# NEX-216 — Contracts (M37): daily diary, observations, milestones, pickup checks, ratios, AI day summaries

**Status:** planned · **Owner:** — · **Branch:** task/NEX-216 · **Depends on:** NEX-210, NEX-214
**Requirements:** M37, O (L2), A-3, A-4, A-5, G-6, V-7, D87 (rule 4)

## Goal
`@nexus/contracts` defines the early-years day captured offline on a carer's phone: diary entries, observations tagged
to milestones, drop-off and pick-up checks against M14 pickup rights, staff-to-child ratios and an AI day summary that
a person sends to the family.

## Build
1. Shared offline fields: `clientId` (UUID), `deviceId` (nullable), `recordedByStaffProfileId`.
2. `DiaryEntryKindSchema` `meal | drink | nap | nappy | toilet | activity | note` (no medication — health data is M61);
   `DiaryEntrySchema` `{ id, tenantId, learnerId, date, kind, occurredAt, amount (none | some | most | all; set iff
   meal | drink), napEndedAt (set iff nap, > occurredAt), nappyState (wet | dirty | dry; set iff nappy), note (≤ 500,
   nullable; personal data), sharedWithFamily, …offline fields, createdAt }`.
3. `ObservationSchema` `{ id, tenantId, learnerIds (unique, 1–10), observedAt, text (1–4000; personal data),
   milestoneOutcomeIds (unique, ≤ 10; accepted by a person), aiSuggestedOutcomeIds (unique, ≤ 10; suggestions only),
   mediaItemIds (unique, ≤ 10; M91), sharedWithFamily, …offline fields, createdAt, updatedAt }`.
4. `MilestoneStatusSchema` `not_yet | emerging | achieved`; `MilestoneProgressSchema` `{ tenantId, learnerId, outcomeId,
   status, achievedOn (set iff achieved), evidenceObservationIds (unique, ≤ 20), assessedByStaffProfileId, updatedAt }`.
5. `PickupCheckSchema` `{ id, tenantId, learnerId, date, kind (drop_off | pick_up), at, collectorKind (guardian |
   authorised_person | staff | transport), collectorRefId (guardian or `AuthorisedPickup` id; set iff guardian |
   authorised_person), verification (photo_id | password | known_to_staff | pin), outcome (released | refused),
   refusedReason (1–300, set iff refused), …offline fields }` — staff confirm the collector; never face recognition.
6. `RatioSnapshotSchema` `{ tenantId, classGroupId, at, childrenPresent, staffPresent (ints ≥ 0), maxChildrenPerStaff
   (1–30, from the region pack), withinRatio (= childrenPresent ≤ staffPresent × maxChildrenPerStaff) }`.
7. `DaySummarySchema` `{ id, tenantId, learnerId, date, aiGenerated: literal true, tier, locale, text (1–3000), sources
   (AssistSource, 1–20), status (draft | sent), sentByStaffProfileId + sentAt (set iff sent) }` — a person sends it.
8. Doc comment: server checks (a pickup by a guardian with `not_allowed` / `court_restricted` rights or an unknown person
   is refused and alerts the manager; observations of several children are shared with each family without the others'
   names; photos follow M91 media consent; AI tagging and summaries need the tenant AI switch and never read M61 data).
   `updatedAt >= createdAt`; strict objects, named exports, ≤ 300 lines, no workspace imports.
