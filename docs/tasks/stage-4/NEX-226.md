# NEX-226 — M29 Curriculum & lesson planning screens (read + draft lesson plans)

**Status:** planned · **Owner:** — · **Branch:** task/NEX-226 · **Depends on:** NEX-222
**Requirements:** M29, M11, O-1 (L2), D15, D42, D71, D72, A-4

## Goal
In demo mode the campus app has a "Curriculum" screen: outcome frameworks with outcomes and CO–PO mappings, the
syllabus with coverage per subject offering, and lesson plans — teachers create and edit draft plans through the outbox.

## Build
1. `modules.ts`: `M29`, path `teaching/curriculum`, icon `Target` (lucide), permission `m29.curriculum.read`, `L2`,
   keys `m29.nav.title` / `m29.nav.summary`, lazy `../modules/m29/CurriculumPage`.
2. `CurriculumPage`: heading, intro, `LastSynced`, `Tabs` "Outcomes" / "Syllabus & coverage" / "Lesson plans" (last tab
   only with `m29.lessonplan.write` or `.review`); "Ask Assist" opens `AssistPanel` (same hide rule as M15).
3. `OutcomesTab`: framework select; outcomes as a tree (`parentId`, code, statement); mappings listed per outcome
   (from → to, strength). `SyllabusTab`: subject-offering select; units in order with topics, each topic's coverage
   status as text + icon (never colour only), and the coverage meter (`percentBps` / 100, one decimal).
4. `LessonPlansTab`: offering select; plans (date, title, status chip, reviewer note when returned); stacked cards at
   360 px. "New lesson plan" / "Edit" (draft or returned plans of the viewer's own staff profile) open `LessonPlanDialog`
   (react-hook-form + zod on `LessonPlanInputSchema`; topics from the offering's syllabus, outcomes from the tenant's
   frameworks; activities add / remove / reorder; `source: "manual"`).
5. Writes (`m29.lessonplan.write`): `POST /lesson-plans` → 201, `status: "draft"`; `PUT /lesson-plans/:id` only while
   `draft` or `returned` (else 409 `conflict`) and only for the caller's own staff profile (else 403). `ofTenant` on the
   offering, topics and outcomes, topics must belong to the offering's subject (else 400 `invalid_request`). Hooks
   `useCreateLessonPlan()` / `useUpdateLessonPlan()` via `useOutboxMutation` (`moduleId: "M29"`, `lww-audited`,
   idempotency headers), invalidating the M29 keys. Offline the dialog still saves (outbox) and says the change is
   queued (new `m29.*` key) — L2.
6. i18n en / hi / ta (D42); tokens only; files ≤ 300 lines; no personal data in errors or logs.
