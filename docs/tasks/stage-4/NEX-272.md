# NEX-272 — M35 tutor settings write: staff configure a course space's AI tutor (contracts, mocks, hook)

**Status:** planned · **Owner:** — · **Branch:** task/NEX-272 · **Depends on:** NEX-262 · screen: NEX-232
**Requirements:** M35, A-1, A-2, A-3, A-5, D87, V-1, V-7 · split from NEX-232 (data side, runs beside the M32/M33 chain)

## Goal
A tutor manager can switch a course space's tutor on or off and set its mode, audience, sources and daily limit.
The tutor can never be switched on while the tenant's AI (or M35 AI) is off, and it can only cite published content.

## Build
1. Contracts: `TutorSettingsInputSchema` strict `{ enabled, mode, audience, sourceContentIds, dailyMessageLimit,
   transcriptsVisibleToStaff }` reusing the field schemas of `TutorSettingsSchema` (no `tenantId`, `courseSpaceId`,
   `updatedBy…`, `updatedAt`). Tests: extra keys rejected; duplicate ids rejected; limit 0 and 201 rejected.
2. `PUT /course-spaces/:id/tutor` (`Idempotency-Key` required, else 400): permission `m35.tutor.manage` (else 403;
   module off → 403 `module_disabled`); space of the viewer's tenant (else 404); viewer has an active staff profile
   (else 403). Saves the input, `updatedByStaffProfileId` = that profile, `updatedAt` = now; creates the row if the
   space has none. Same-key replay by the same staff profile returns the stored settings (200).
3. Guards: `enabled: true` while the tenant's `aiSettings.enabled` is false, `modules.M35` is not true, or M35 is in
   `blockedModules` → 409 `conflict` (A-1). Every `sourceContentIds` entry must be a `published` content item of the
   tenant, else 422 with path `sourceContentIds.<index>` (A-5). Switching off is always allowed.
4. Invalid bodies → 422 with field paths and a fixed message only (V-7).
5. Hook `useSaveTutorSettings()` → `{ courseSpaceId, input }`; online only (plain `useMutation`,
   `networkMode: "always"`; offline → error "Connect to save"), a new key per call via `idempotencyHeaders`;
   invalidate `m35.tutorSettings(courseSpaceId)`.
