# NEX-270 — M33 learner test-taking screen + API guide for the NEX-269 endpoints

**Status:** planned · **Owner:** — · **Branch:** task/NEX-270 · **Depends on:** NEX-230, NEX-269
**Requirements:** M33, O-1 (L2), D15, D42, D71, D72, V-7, WCAG 2.2 AA · split from NEX-230 (taking a test)

## Goal
A learner can start an open test from the test view, answer every question kind, flag, move between items, see the
time left, and submit — answers queue offline and sync (L2). Documents the NEX-269 endpoints.

## Build
1. `OnlineTestView`: for a learner viewer, "Start test" when the test is open, inside its window and attempts are
   left; "Resume" when an own attempt is `in_progress`; else a reason text (closed, not open yet, no attempts left).
   Start is online only: offline → disabled with "Starting a test needs a connection". Start sends a new `clientId`.
2. `TakeTest` (`useAttemptDelivery`): test title, item n of N, section title, a list of item buttons showing
   answered / flagged (text + icon, not colour only), previous / next, "Flag for review" toggle; time left from
   `deadlineAt` (none → "No time limit"), announced politely at 5 and 1 minutes (`aria-live`); at the deadline the
   inputs lock and it submits once. Marks per item and the negative-marking note (`negativePoints` > 0) shown.
3. `QuestionAnswer` per kind: single_choice / true_false radio group; multiple_choice checkboxes; short_text input;
   numeric input (locale number parsing, invalid → field error, not saved); essay textarea; order → up / down buttons
   per option (keyboard, no drag-only). Stem and option text rendered as plain text (no HTML).
4. Saving: on change (text debounced 800 ms) `useSaveAnswer` with the current answer + `flagged`; a per-item state
   "Saved" / "Saved on this device — will sync" (queued) / "Not saved, retry". 409 (deadline passed) → lock + notice.
5. `SubmitDialog`: counts of unanswered and flagged items, confirm → `useSubmitAttempt`; afterwards a done screen:
   "Submitted" and score `x / max` only when the response carries `scorePoints`, else "Results not released yet".
6. Never put answer text in logs, telemetry, error toasts or URLs (V-7). i18n en / hi / ta (D42); tokens only;
   files ≤ 300 lines; 360 px usable; RTL ok; tests use `await screen.findBy…`; run each m33 test file alone.
7. API.md: request / response shapes, status codes (201 / 200 idempotent / 404 / 409 / 422) and the no-answer-key rule.
