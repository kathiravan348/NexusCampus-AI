# NEX-210 — Contracts (M29): outcome frameworks, outcomes, CO–PO mapping, syllabus units, lesson plans, coverage

## Goal
`@nexus/contracts` defines the Stage 4 curriculum spine — outcomes that later modules tag, syllabus, lesson plans and
coverage — with the same shapes for every institution type.

## Build
1. `OutcomeCodeSchema` `/^[A-Za-z0-9][A-Za-z0-9._:-]{0,63}$/` (CASE codes such as `CCSS.MATH.5.NBT.A.1`, `CO3`, `PO-12`).
2. `OutcomeFrameworkKindSchema` `standards | course_outcomes | program_outcomes | milestones | skills`;
   `OutcomeFrameworkSchema` `{ id, tenantId, institutionId (nullable = whole group), code (AcademicCode), name, kind,
   source (local | case_import), caseDocumentUri (https, set iff case_import), version (1–32), active, createdAt, updatedAt }`.
3. `OutcomeSchema` `{ id, tenantId, frameworkId, parentId (nullable, ≠ id), code (OutcomeCode), statement (trimmed 1–2000),
   order (int ≥ 1), caseItemId (UUID, nullable), subjectIds, yearLevelIds (each unique, ≤ 20), createdAt, updatedAt }`.
4. `OutcomeMappingSchema` (CO → PO) `{ id, tenantId, fromOutcomeId, toOutcomeId (≠ from), strength (1 | 2 | 3), createdAt }`.
5. `SyllabusTopicSchema` `{ id, title (1–200), order (int ≥ 1), outcomeIds (unique, ≤ 20) }`; `SyllabusUnitSchema`
   `{ id, tenantId, subjectId, yearLevelId (nullable), code, title, order, plannedHours (0–500 in 0.5 steps, nullable),
   outcomeIds (unique, ≤ 50), topics (1–100; unique ids and orders), createdAt, updatedAt }`.
6. `LessonActivityKindSchema` `intro | instruction | practice | discussion | assessment | other`;
   `LessonPlanStatusSchema` `draft | submitted | approved | returned | delivered`. `LessonPlanInputSchema`
   `{ subjectOfferingId, staffProfileId, date (IsoDate, nullable), timetableSlotId (nullable), title, topicIds (unique,
   1–20), outcomeIds (unique, ≤ 20), objectives (≤ 2000), activities (≤ 30 of `{ order, title (1–200), minutes (1–600),
   kind }`, unique order), resources (≤ 2000), source (manual | ai_draft) }`. `LessonPlanSchema` = input + `{ id,
   tenantId, status, reviewedByStaffProfileId, reviewedAt, reviewNote (≤ 1000, nullable), createdAt, updatedAt }`;
   reviewer + time set iff `approved | returned`; `reviewNote` required when `returned`.
7. `CoverageStatusSchema` `not_started | in_progress | covered`; `CoverageEntrySchema` `{ id, tenantId,
   subjectOfferingId, topicId, status, coveredOn (IsoDate, set iff covered), lessonPlanId (nullable), updatedAt }`;
   `SyllabusCoverageSchema` `{ subjectOfferingId, topicsTotal (int ≥ 0), topicsCovered (≤ total), percentBps (0–10000,
   = round(covered × 10000 / total), 0 when total is 0) }`.
8. `updatedAt >= createdAt` (`Date.parse`). Doc comment: server checks (codes unique per framework, parent in the same
   framework, no cycles, CO → PO kinds, topics of the offering's subject); `ai_draft` plans are saved only by a person.
9. Strict objects, `XSchema` + `type X`, named exports, file ≤ 300 lines, no imports of other workspace packages.
