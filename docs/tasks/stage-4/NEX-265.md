## Build
1. `ids-stage4-engage.ts`: every new id as a named constant (D16); data files never use id literals.
2. `surveys.ts` (Riverside and Northbridge): every schema in `surveys.ts`; every survey kind and anonymity value; one
   anonymous survey whose responses carry no person or device and only a day; one confidential survey; one result set
   below `minResponsesToShow` (suppressed) and one above; one AI theme summary built from ≥ `minResponsesToShow`
   responses that quotes no one; one faculty survey about a staff profile with results only for that staff member and
   their manager (A-4: no appraisal decision rows).
3. `credentials.ts` (Riverside and Northbridge): every schema in `credentials.ts`; every kind, format and issued
   status; one revoked credential; one learner-hidden credential; proofs reference only a public key
   (`verificationMethod` is the only URL / DID field allowed); verifications for a valid, a revoked and an unknown code
   with the same answer shape and no learner data. No key material anywhere.
4. `portfolios.ts`: add the deferred Riverside entries — one `assignment_submission` (refId = an `ASSIGNMENT_SUBMISSIONS`
   row of the same learner and tenant) and one `credential` (refId = a `credentials.ts` row of the same learner);
   `stage4-care.test.ts`: add both kinds to the `covers(PF.PORTFOLIO_ENTRIES, …)` list (drop the "NEX-258 adds" comment)
   and check each ref resolves to a row of the portfolio's learner.
5. Staff are the tenant's `rp-…-staff` role profiles; learners from `LEARNERS`, guardians from `GUARDIAN_RELATIONSHIPS`;
   dates inside each tenant's calendar year; `CREATED_AT` / `UPDATED_AT` from `tenants.ts`; fictional text; files ≤ 300
   lines. D87 rule 5: imported by path, not added to `fixtures/index.ts`; no `DEMO_FIXTURES_VERSION` bump; no backend.
