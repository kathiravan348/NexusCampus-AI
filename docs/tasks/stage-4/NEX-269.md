## Build
1. Contracts: `StartAttemptInputSchema` strict `{ clientId: uuid }`; `TestAnswerInputSchema` strict `{ selectedOptionIds,
   textAnswer, numericAnswer, flagged }` (same field rules as `TestResponseSchema`); `AttemptDeliverySchema` strict
   `{ attempt: TestAttemptSchema, deadlineAt: UtcDateTime | null, sections: [{ id, title, items: QuestionDelivery[] }],
   answers: TestResponse[] }`. Tests: a delivery item with `correct` / `acceptedAnswers` keys is rejected.
2. Learner = the viewer's own `learners` row (`personId`), enrolled in the test's course space. Staff, guardians
   (even with linked learners), another tenant, unknown or `draft` test → 404; no `m33.test.read` → 403.
3. `POST /online-tests/:id/attempts` (201): test `open` and now within `opensAt…closesAt`, attempts used <
   `attemptsAllowed` (null = unlimited), no other `in_progress` attempt (else 409 `conflict`). Same `clientId` → the
   same attempt (idempotent, 200). Items: fixed `itemIds` in order; pool sections take `itemCount` `approved` items of
   the pool banks (and outcomes when set), order seeded by attempt id; options shuffled when `shuffleOptions`
   (seeded, except `order` items always shuffled). Returns `AttemptDelivery`.
4. `GET /attempts/:id/delivery`: own `in_progress` attempt only (else 404), same item set and order as at start.
5. `PUT /attempts/:id/responses/:itemId` (`Idempotency-Key`): own `in_progress` attempt, item in its delivery (else
   404), before `deadlineAt` = min(`startedAt` + time limit, `closesAt`) (else 409); option ids must exist on the item
   (else 422, field paths only). Upserts one `TestResponse` with `autoScore`/`manualScore` null; returns it.
6. `POST /attempts/:id/submit` (empty body, idempotent): sets `submitted` (`auto_submitted` after `deadlineAt`) and
   `submittedAt`; auto-scores choice / true-false / order / numeric / short-text responses into the stored rows
   (negative marking floored per item at −`negativePoints`); `scorePoints` stays null unless `resultsVisible` and no
   essay item. The response never carries scores or keys when results are hidden.
7. Hooks: `useStartAttempt()` (online only — needs the questions), `useAttemptDelivery(attemptId)`, `useSaveAnswer()`
   and `useSubmitAttempt()` via `useOutboxMutation` (`moduleId: "M33"`, idempotency headers, as the m29 hooks),
   invalidating attempts and delivery; offline they queue (L2). Answer text never in logs, telemetry or errors (V-7).
