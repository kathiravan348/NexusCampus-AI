## Build
1. `ids-stage4-assess.ts`: every new id as a named constant (D16); data files never use id literals.
2. `assignments.ts`: `ASSIGNMENTS` (each status; Riverside one with anonymous peer review, Northbridge one with an
   originality check), `ASSIGNMENT_SUBMISSIONS` (each status, files as metadata only), `SUBMISSION_FEEDBACK`,
   `AI_MARKING_SUGGESTIONS` (one accepted, one changed, one rejected, one pending — the mark is always the person's),
   `PEER_REVIEWS`, `ORIGINALITY_SIGNALS` (demo provider key, external id only — D87 rule 1).
3. `question-tests.ts`: `QUESTION_BANKS`, `QUESTION_ITEMS` (every kind; one `ai_generated` still in review; Apex items
   with negative-marking penalties, NEX-256), `ONLINE_TESTS` (each mode; Apex a timed mock with sections and pools),
   `TEST_ATTEMPTS` (each status; one Apex attempt with a negative score part), `TEST_RESPONSES`, `ITEM_STATISTICS`.
4. `tutor.ts`: `MASTERY_RECORDS` (each level, outcomes from NEX-220), `LEARNING_PATHS` (steps of each kind and
   status), `TUTOR_SETTINGS` (per tenant; Little Steps tutor off), `TUTOR_SESSIONS` and `TUTOR_MESSAGES` (AI messages
   labelled with sources; minors only where guardian consent is recorded in the session; one message with a safety
   category that was blocked) — A-3.
5. `early-warning.ts`: `ENGAGEMENT_SNAPSHOTS`, `RISK_SCORES` (each level and review status, ≥ 2 factors with reasons,
   one expired), `INTERVENTIONS` (each status, every one created by a staff person — A-4, A-5). No Little Steps rows.
6. Course items, outcomes, offerings, learners and staff come from NEX-220 / Stage 3 sets of the same tenant;
   `CREATED_AT` / `UPDATED_AT` from `tenants.ts`; dates inside each tenant's calendar year; fictional, non-identifying
   text; files ≤ 300 lines.
7. D87 rule 5: export from `fixtures/index.ts` for MSW only — not in `demoFixtures()`, no `DEMO_FIXTURES_VERSION` bump,
   nothing in `backend/`.
