## Goal
`@nexus/mocks` has demo data in the M42 and M43 contract shapes, tied to the Stage 3 and Stage 4 records, so the later
handlers and screens have realistic, privacy-safe records.

- `AGENTS.md` §7–§9; `frontend/packages/contracts/src/{higher-ed,store}.ts` (header rules and refinements)
- NEX-258 (the pattern): `frontend/packages/mocks/src/fixtures/{ids-stage4-more,library,session-courses,test-prep,`
  `stage4-more.test}.ts`; `{ids,ids-stage3,tenants,calendars,role-profiles,families,consents,academics,assignments,`

## Files
Create in `frontend/packages/mocks/src/fixtures/`: `ids-stage4-store.ts`, `higher-ed.ts`, `store.ts`,
`stage4-store.test.ts`. Modify nothing else.

## Build
1. `ids-stage4-store.ts`: every new id as a named constant (D16); data files never use id literals.
2. `higher-ed.ts` (Northbridge, the `he` tenant): one row or more of every record schema in `higher-ed.ts` (programme
   requirements, registration windows, elective registrations, degree audits, theses, path advice); every value of
   each status / stage enum and at least two credit systems; programmes, years, periods, subjects and offerings from
   `academics.ts`; one thesis citing an `ORIGINALITY_SIGNALS` row of Northbridge (or `null` if none exists); a degree
   audit whose verdict follows from its numbers; path advice only for adults or minors whose guardian granted
   `ai_features`, with reasons (A-5), and one reviewed by an advisor staff profile, one not yet reviewed (A-4).
3. `store.ts` (Apex and Harmony, the `tp` / `sk` tenants): every record schema in `store.ts` (products of each kind,
   coupons, orders with lines, subscriptions, affiliates, affiliate conversions); every order and subscription status;
   `refIds` resolve to course spaces (`courses.ts`), Harmony `SESSION_PACKS` (`session-courses.ts`) or, for a bundle,
   other products of the same tenant; buyers are adults (a guardian buys for a minor); `gatewayReference` is a fictional
   opaque token with no card data; money in integer minor units with the tenant's currency (D9); one AI-drafted product
   page published by a staff member, one AI draft not published (A-4).
4. Staff are the tenant's `rp-…-staff` role profiles; learners from `LEARNERS`, guardians from `GUARDIAN_RELATIONSHIPS`;
   dates inside each tenant's calendar year; `CREATED_AT` / `UPDATED_AT` from `tenants.ts`; fictional text; no URL,
   key or password; files ≤ 300 lines.
5. D87 rule 5: imported by path, not added to `fixtures/index.ts`; not in `demoFixtures()`, no `DEMO_FIXTURES_VERSION`
   bump, nothing in `backend/`.
