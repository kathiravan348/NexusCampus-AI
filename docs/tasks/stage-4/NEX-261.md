# NEX-261 — M29 lesson-plan workflow: submit, approve / return, delivered, coverage updates

**Status:** ready-for-review · **Owner:** Codex · **Branch:** task/NEX-261 · **Depends on:** NEX-226

## Goal
In demo mode a teacher submits a lesson plan, a reviewer approves or returns it with a note, and the teacher marks an
approved plan delivered, which marks its topics covered in the syllabus coverage.

## Build
1. Contracts: `LessonPlanSubmitInputSchema` = `{}` strict; `LessonPlanReviewInputSchema` = `{ decision: "approve" |
   "return", note: string 1–1000 | null }`, note required when `return`; `LessonPlanDeliveredInputSchema` =
   `{ deliveredOn: IsoDate }`. Contract tests for each rule.
2. Handlers (same `runWrite` guard: entitlement, permission, active staff profile; tenant-scoped lookup, else 404):
   - `POST /lesson-plans/:id/submit` — `m29.lessonplan.write`, own plan only (403), `draft`/`returned` → `submitted`
     (else 409); clears review fields as the contract requires.
   - `POST /lesson-plans/:id/review` — `m29.lessonplan.review`; `submitted` only (409); a reviewer never reviews
     their own plan (403); sets `approved` / `returned`, reviewer, `reviewedAt`, note.
   - `POST /lesson-plans/:id/delivered` — `m29.lessonplan.write`, own plan, `approved` only (409); `deliveredOn` not
     in the future (400); sets `delivered` and, for each topic, the offering's coverage entry to `covered`,
     `coveredOn`, `lessonPlanId` (create the entry if missing); `GET /syllabus-coverage` then reflects it.
   - Idempotency receipts like NEX-226 (per tenant + plan + key); error texts carry no plan text or personal data.
3. Services: `useSubmitLessonPlan`, `useReviewLessonPlan`, `useMarkLessonPlanDelivered` via `useOutboxMutation`
   (`moduleId: "M29"`, `lww-audited`, idempotency headers), invalidating the M29 keys; offline they queue (L2).
4. Screens: `LessonPlanActions` on each plan card — Submit / Mark delivered for the owner by status; Approve / Return
   for viewers with `m29.lessonplan.review` on others' submitted plans. `LessonPlanReviewDialog`: decision + note
   (react-hook-form + zod; note required to return). Queued-offline toast reuses the NEX-226 pattern.
5. i18n en / hi / ta (D42); tokens only; files ≤ 300 lines; status as text + icon, never colour only.
