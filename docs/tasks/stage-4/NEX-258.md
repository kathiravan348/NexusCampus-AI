2. `library.ts` (Riverside and Northbridge): one row or more of every record schema in `library.ts` (catalogue records,

   confirmed by a staff member; recommendations only for learners whose
   guardian granted `ai_features` in `CONSENTS` (or adults), built only from that learner's own loans; no fine for a
   minor where the tenant's region forbids it (if the contract or region data says so).

   weak-topic plans, parent reports); each status; a rank row for a learner without leaderboard consent shows no name
   (G-6); AI answers labelled, citing batch content (A-5); one plan shared by a teacher, one AI draft not shared (A-4).
4. `session-courses.ts` (Harmony): every record schema in `session-courses.ts` (catalogue courses, packs, purchases,
   sessions, bookings, level exams, practice feedback); every status and session kind (regular, trial, make-up);
   bookings within each session's capacity; one practice feedback AI draft not shared, one shared by a teacher.
5. Staff are the tenant's `rp-…-staff` role profiles; learners from `LEARNERS`, guardians from
   `GUARDIAN_RELATIONSHIPS`; invoices (if a schema refers to one) from the Stage 3 fee fixtures of the same tenant;
   dates inside each tenant's calendar year; `CREATED_AT` / `UPDATED_AT` from `tenants.ts`; fictional, non-identifying
   text; no URL, key or password; files ≤ 300 lines (split a module into two files inside `Files` names only if needed
   — ask first).
6. D87 rule 5: imported by path, not added to `fixtures/index.ts`; not in `demoFixtures()`, no `DEMO_FIXTURES_VERSION`
   bump, nothing in `backend/`.

What approved contract shape should represent an anonymised loan? The contract is outside this task’s editable files.
  - answered by the planner: Do not add an anonymised loan. `LoanSchema` stays as it is: anonymising returned loans
    after the retention period is a server retention job (it removes the borrower link), not a fixture row. The
    Build 2 example and the matching acceptance check are removed; every loan keeps a borrower in the same tenant.
- The board and task both say `changes-requested`, but the Review section contains only the template placeholder. Which numbered change requests should be addressed?
  - answered by the planner: There are no review change requests; `changes-requested` only marks that the planner
    answered your questions. Build the task as written in `Build` and `Acceptance checks` (with the anonymised-loan
    example removed as answered above), then set `ready-for-review`.

- Which M33 online-test fixture and M30/M31 batch-content fixture may this task read to resolve Apex test IDs, section IDs and AI-answer citations? The current read list and its fixture imports do not include those records.
  - answered by the planner: Read (do not change) `question-tests.ts`, `question-tests-attempts.ts`, `content.ts`,
    `courses.ts` and their id files (`ids-stage4-assess.ts`, `ids-stage4-learning.ts`). `testIds` come from the Apex rows
    of `ONLINE_TESTS` (`OT.axMock`, `OT.axAdaptive`); `sectionScores[].sectionId` from those tests' `sections`; doubts
    use Apex course spaces / question items; AI-answer `sources` cite Apex `CONTENT_ITEMS` or `QUESTION_ITEMS` with the
    matching `moduleId`. The test checks each of these references exists and belongs to Apex.
- Which Harmony M91 practice recordings should the draft and shared feedback reference? The permitted M91 fixture has no Harmony recordings. May this task define supporting staff-only recordings for adult Harmony learners inside `session-courses.ts`?
  - answered by the planner: Yes. Add the ids to `ids-stage4-more.ts` and export `HARMONY_PRACTICE_MEDIA` from
    `session-courses.ts`: `audio` or `video` items parsed by the M91 `MediaItemSchema` in `portfolios.ts`,
    `visibility: "staff_only"`, tagged only with the adult Harmony learner whose feedback cites it, Harmony staff as
    uploader, no URL. Do not add them to `MEDIA_ITEMS` or `portfolios.ts`. The test checks every `mediaItemId`
    resolves to one of these rows, same tenant and learner.
