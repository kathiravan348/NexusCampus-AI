# NEX-181 — Menu shows only screens the user can open (role-profile audience, D77)

**Status:** planned · **Owner:** — · **Branch:** task/NEX-181 · **Depends on:** NEX-160–178
**Requirements:** V-1 (deny by default), G-1, D77; M13, M14, M18, M21–M23, M25–M27; `AGENTS.md` §9

## Goal
Every menu link opens a screen for that user. Today modules with `permission: null` show in every menu, and the mock
API then answers 403 ("No access"), e.g. admin → `/family`, teacher → `/fees`, guardian → `/staff`, `/learner`;
learner → `/families` (404s for a sibling's pickups). Found by the NEX-179 persona smoke (`e2e/personas.spec.ts`).

## Build
1. `audience?: { readonly kinds: readonly RoleProfileKind[]; readonly notStaff?: boolean }` (type from
   `@nexus/contracts`). Doc comment: the entry is permitted when the user holds `permission`, **or** has an `active`
   role profile in the current tenant whose `kind` is in `kinds` (and, with `notStaff`, no active `staff` profile).
   An entry with `audience` and `permission: null` is permitted only through `audience`. No `audience` → unchanged.
2. Values (permission · audience):
   - M13 `learners`: `m13.learner.read` · guardian, learner, notStaff
   - M14 `families`: `m14.family.read` · guardian, notStaff
   - M18 `fees`: `m18.fees.read` · guardian, learner, notStaff
   - M21 `exams`: `m21.exams.read` · M22 `report-cards`: `m22.reports.read` · M23 `documents`:
     `m23.documents.read` — each · guardian, learner, notStaff
   - M25 `family`: `null` · guardian · M26 `learner`: `null` · learner · M27 `staff`: `null` · staff
   - M24 `messages` stays `permission: null`, no audience (every role holds the M24 read codes).
3. Menu and route use the same `isPermitted` (no second rule); a hidden entry's URL shows `Forbidden` as today.
4. Do not change screens, handlers, fixtures or contracts. If a rule above contradicts a handler, write it under
   `Questions` (`- ` line) and stop.
