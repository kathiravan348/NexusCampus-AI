# NEX-190 — Build: DB + API for M22 report cards and M23 issued documents

**Status:** planned · **Owner:** — · **Branch:** task/NEX-190 · **Depends on:** NEX-189, NEX-207 (migration chain)
**Requirements:** M22, M23, G-6, V-1, V-2, V-7, D78, D80

## Goal
Report cards and issued documents are stored per tenant under forced RLS and served by the real backend with the same
responses, errors, family scope and order as the mock: report card status changes (approve, publish, withdraw) and
document revocation. Remarks and revocation reasons are personal data: encrypted, never logged.

## Build
1. Migration `0037`: `report_cards` (`lines` JSONB 1–60 of subject, grade, marks percent; the line remarks as one
   encrypted JSON array `line_remarks`; encrypted `overall_remark`; status; `published_at` iff published) and
   `issued_documents` (optional learner, kind, number, template, issue date, `signatures` JSONB ≤ 5, verification code
   `^[A-Z0-9]{10,16}$` unique, `revoked` iff encrypted `revoked_reason`). Composite `(id, tenant_id)` references.
   ENABLE + FORCE RLS, `tenant_isolation`; `nexus_app` SELECT; `UPDATE (status, published_at, updated_at)` on report
   cards and `UPDATE (revoked, revoked_reason)` on documents only.
2. `GET /report-cards?learnerId=&classGroupId=` and `GET /issued-documents?learnerId=` (module only) as the mock:
   read permission sees all (class group filter `404` when unknown; same year and enrolled learners); families only
   their learners (report cards published only; documents with `revokedReason` null). Decrypted remarks / reasons
   are audited once per page (`m22.reportCard.sensitiveRead`, `m23.issuedDocument.sensitiveRead`).
3. `POST /report-cards/:id/status` in the mock's order: module → `m22.reports.publish` → card `404` → body `400`
   (path `status`, "Invalid status") → transition from the previous status else `409` (path `status`, "Invalid
   transition") → `published_at` now when published, else null → `200`. Audit `m22.reportCard.statusChanged`.
4. `POST /issued-documents/:id/revoke` in the mock's order: module → `m23.documents.issue` → document `404` → already
   revoked `409` (path `revoked`) → body `400` (path `reason`) → store the encrypted reason → `200` with the reason.
   Audit `m23.issuedDocument.revoked` (`reason` marked sensitive).
5. Tests (real DB): lists, filters, family scope and masking; every transition and its `409`; revoke and its errors;
   ciphertext and `ENCRYPTED_COLUMNS`; sensitive-read audit; tenant B isolation; forced RLS and grants; models.
