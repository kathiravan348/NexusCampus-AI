# NEX-167 — M18 Fees & payments screens (staff desk + family view, offline L2 receipts)

**Status:** ready-for-review · **Owner:** Gemini · **Branch:** task/NEX-167 · **Depends on:** NEX-158, NEX-166
**Requirements:** M18, M11, O-1 (L2), O-2, V-7, G-6, D9, D42, D71, D72, D75

## Goal
In demo mode the campus app has a "Fees" screen: staff see invoices, payments, plans and refunds and record a cash /
cheque / bank-transfer receipt (queued offline, L2); guardians and learners see only their family's invoices and payments.

## Build
1. `modules.ts`: `M18`, path `fees`, icon `Wallet` (lucide), permission `null` (family viewers too; the handlers
   decide), `L2`, keys `m18.nav.title` / `m18.nav.summary`, lazy `../modules/m18/FeesPage`.
2. `FeesPage`: heading, intro, `LastSynced` (invoices query), "Ask Assist" (as `ConfigPage`), tabs Invoices /
   Payments, plus Plans & refunds only with `m18.fees.read`. Invoices 403 → existing no-access message.
3. `InvoicesTab`: status filter (`useFeeInvoices(null, status)`); invoice number, learner name via `usePeople()`
   (absent → number only), due date, total / paid / balance with `formatMoney`, status badge with text; open row shows
   lines. `PaymentsTab`: receipt number, amount, method as text, received date (tenant time zone), status badge.
   `PlansTab`: fee heads, plans (lines, instalments), concessions (kind, mode, value — never `reason`), refunds
   (amount, status — never `reason`) (V-7).
4. Contract: `FeePaymentInputSchema` = `{ invoiceIds, currency, amount, method, receivedAt, deviceId }`, `method` limited
   to `cash`, `cheque`, `bank_transfer`; reuse the duplicate-ids refine as a named function (shared with `FeePaymentSchema`).
5. `POST /fee-payments` (entitlement M18, `m18.fees.manage`, active staff profile else 403): every invoice in the
   tenant, status `issued` / `part_paid`, same currency (else 400 `invalid_request`, top-level path only);
   `amount` ≤ sum of balances (else 400, path `amount`). Creates a `succeeded` payment (`payerPersonId` = the first
   invoice's learner's `personId`, `gatewayReference: null`, `receiptNumber` `R-` + 6 digits),
   applies it to the invoices oldest due first and updates `paid` / `status` so `FeeInvoiceSchema` still parses.
   201 with the payment. Repeated `Idempotency-Key` in the tenant → the first payment, nothing applied twice.
6. Service `useRecordFeePayment()` via `useOutboxMutation` (`moduleId` `M18`, operation `fees.payment`, `mergeRule`
   `append-only`, priority `high`, idempotency header); invalidates the M18 keys on success. `deviceId` = the
   outbox device id when queued, else `null`.
7. `RecordPaymentDialog` (react-hook-form + zod; only with `m18.fees.manage`): invoices of one learner (multi-select of
   `issued` / `part_paid` invoices), amount in major units → minor, method, received at (default now). Offline: allowed, shows
   "Waiting to sync" until replayed. Field errors from the schema and the 400 details.
8. i18n en / hi / ta (D42); tokens only; files ≤ 300 lines; 360 px stacked, RTL ok; no names, amounts per person,
   refund / concession reasons or ids in console, errors or test names (V-7, G-6). No card / UPI / gateway capture.
