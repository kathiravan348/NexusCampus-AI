## Build
1. Migration `0028`: `enquiries`, `applications`, `admission_offers`, `waitlist_entries`; columns as the contract
   (snake_case); composite `(id, tenant_id)` references to institutions, campuses, programs, academic years, year
   levels, class groups, people, staff `role_profiles`, `form_definitions`, and between the four tables; check constraints
   for the contract's rules (contact phone or email; `lost_reason` exactly when lost; `submitted_at` / `decided_at` /
   `responded_at` by status; unique ids in arrays; waitlist position ≥ 1, unique per program). Application answers
   as in M13: sensitive custom field values as `FieldCipher` text, others JSONB. ENABLE + FORCE RLS,
   `tenant_isolation`; `nexus_app` SELECT, plus INSERT on `enquiries` only.
2. Routes (module `M12`, `m12.admissions.read`, paged): `GET /enquiries?status=`, `/applications`,
   `/admission-offers`, `/waitlist` — same filters and order as the mock.
3. `POST /enquiries` (`m12.admissions.manage`) in the mock's order: module, permission, then body; `400
   invalid_request` (bad JSON → path `""`; field details use input paths only, never user-typed values); a campus or
   program outside the tenant → `400` with that path. As the mock: the viewer's staff `role_profiles` row (kind
   `staff`) is the assignee and gives the institution; without one, assignee null and the tenant's first
   institution by id. Server sets tenant, `enq-` id via `nexus.core.ids`, timestamps, `status: new`, `campaignCode`
   and `lostReason` null. `201` returns the stored row.
4. Audit `m12.enquiry.created` (field names only, no values) in the same transaction.
5. Tests (real DB): routes, paging, status filter; create + read back + audit; missing contact; foreign campus /
   program → `400` path; no manage → `403`; module off → `403 module_disabled`; guard before body; tenant B
   isolation; forced RLS on all four tables; sensitive answers stored as ciphertext; models match the schema.

## Questions
For `POST /enquiries`, which institution owns the enquiry when the viewer is staff at institution A and selects a program at institution B in the same tenant? Build step 3 specifies A (staff institution, then first tenant institution by id). The frozen mock selects B (program, then campus, then staff, then first tenant institution). Which precedence should the backend implement?
answered by the planner: follow the frozen mock (D78). Institution = the program's institution, else the campus's, else the viewer's staff `role_profiles` institution, else the tenant's first institution by id; none → `400 invalid_request`. The assignee is still the viewer's staff `role_profiles` row (or null). Build step 3 is corrected by this answer.

May Codex read the existing backend test sign-in helper and its client/Keycloak fixture definitions, or can the planner provide their import paths and usage for a staff manager and a viewer without manage permission? The M12 fixture hand-builds a session that the backend rejects. The harness shows a working `sign_in(client, kc)` call, but its fixture setup is outside the NEX-185 file list.
