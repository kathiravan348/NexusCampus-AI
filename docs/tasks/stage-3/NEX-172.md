## Build
1. `modules.ts`: `M23`, path `documents`, icon `FileBadge` (lucide), permission `null` (family viewers too; the handler
   decides), `L1`, keys `m23.nav.title` / `m23.nav.summary`, lazy `../modules/m23/DocumentsPage`.
2. `DocumentsPage`: heading, intro, `LastSynced` (issued documents query). Staff with `m23.documents.read`: learner
   select (`useLearners()` + `usePeople()`, "All learners" default) and kind select (client-side filter); family:
   learner select only when more than one child. 403 → the existing no-access message.
3. `DocumentList`: rows of kind as text (`m23.kind.<kind>` keys for all 7 kinds), number, issued date (tenant
   formatting), learner name (else learner number; "Staff letter" when `learnerId` is null), "Revoked" text badge.
   `?document=` opens `DocumentView`.
4. `DocumentView`: kind, number, issued date, verification code, signatures count with method as text
   (`m23.method.<method>`), "Revoked" badge. `revokedReason` shown only to staff with `m23.documents.read` (V-7);
   never to families, never in logs.
5. Contract: `IssuedDocumentRevokeInputSchema` = strict `{ reason }`, same bounds as `revokedReason` (trim, 1…300).
6. `POST /issued-documents/:id/revoke` (entitlement M23, permission `m23.documents.issue`, else 403): document in the
   tenant (else 404); already revoked → 409 `conflict`, path `revoked`; invalid body → 400 `invalid_request`, path
   `reason`. Sets `revoked` true and `revokedReason`; 200 with the document (parse with `IssuedDocumentSchema`).
   The family GET path strips `revokedReason` (null) in its response map, as m20 does for `remark`. Errors carry paths
   only, never names, numbers or the reason.
7. Service `useRevokeIssuedDocument(documentId)`: online mutation (as NEX-171), invalidates the `queryKeys.m23` prefix.
8. `RevokeDialog` (only with `m23.documents.issue`, not on revoked documents): reason textarea (required, ≤ 300,
   counter), confirm text says the public verification will show the document as invalid; disabled offline with
   `common.offline`; 409 → "Already revoked, reload" message.
9. i18n en / hi / ta (D42); tokens only; files ≤ 300 lines; 360 px stacked, RTL ok; touch targets ≥ 44 px; no names,
   numbers, codes, reasons or learner ids in console, errors or test names (V-7, G-6).

## Questions
- The family GET must return `revoked: true` with `revokedReason: null`. Both the GET handler and the service parse that response with `IssuedDocumentSchema`, which rejects this combination, and its existing contract test enforces the rejection. The task limits contract changes to the revoke input schema. May I add a separate redacted read schema for the GET handler and service, preserving the strict stored-document and POST contract?
  (Yes — answered by the planner 2026-11-24.) Add `IssuedDocumentReadSchema` to `records.ts` (+ a test): the same
  strict object as `IssuedDocumentSchema` but with the refine `revokedReason === null || revoked` (a reason only on a
  revoked document; a revoked one may have `null`). Build it from one shared base object so the fields stay in one
  place. Use it in the GET handler's page schema and in the service list hook; the POST response and stored rows stay
  on the strict `IssuedDocumentSchema`; the existing contract test stays. Add it to `docs/CONTRACTS.md`. This file
  change is in scope for NEX-172.
