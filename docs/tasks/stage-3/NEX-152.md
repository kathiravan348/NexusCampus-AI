# NEX-152 — Contracts (M20–M23): grading schemes, marks, rubrics; exams and seating; report cards; documents and e-sign

**Status:** planned · **Owner:** — · **Branch:** task/NEX-152 · **Depends on:** NEX-148
**Requirements:** M20, M21, M22, M23, G-4, V-7, D72

## Goal
`@nexus/contracts` defines how learning is assessed and recorded: grading schemes and marks (M20), in-person exams
and seating (M21), report cards (M22) and issued documents with e-signature and a verification code (M23).

## Build
1. `assessment.ts` — `GradeBandSchema` `{ code (1–8), label (1–40), minPercent, maxPercent (0–100, min ≤ max),
   gradePoint (0–10 in steps of 0.1, nullable) }`; `GradingSchemeSchema` `{ id, tenantId, institutionId, name, kind
   (percent | letter | gpa | descriptor | competency), bands (1–20, non-overlapping, together 0–100), createdAt,
   updatedAt }`.
2. `AssessmentSchema` `{ id, tenantId, subjectOfferingId, name, kind (test | assignment | project | practical | oral
   | observation), maxMarks (number 1–1000, steps of 0.5), weightPercent (0–100), rubricId (nullable), dueOn
   (nullable), status (draft | open | marking | moderated | published), createdAt, updatedAt }`.
3. `RubricSchema` `{ id, tenantId, name, criteria: (1–20) `{ code, label, levels: (2–6) `{ score (int 0–10),
   descriptor (1–200) }` }` }`; `MarkEntrySchema` `{ id, tenantId, assessmentId, learnerId, marks (0–maxMarks is a
   server check; here ≥ 0, steps of 0.5, nullable), absent, rubricScores (record code → int, nullable), remark (≤ 500,
   nullable; personal data), enteredByStaffProfileId, enteredAt, deviceId (nullable, offline L2) }`; refine: `absent`
   ⇒ `marks` null.
4. `exams.ts` — `ExamSchema` `{ id, tenantId, institutionId, academicYearId, name, startsOn, endsOn (≥ startsOn),
   status (planned | scheduled | running | results_pending | published), createdAt, updatedAt }`;
   `ExamPaperSchema` `{ id, tenantId, examId, subjectOfferingId, date, start, end (TimeOfDay, end > start), roomIds
   (unique, ≤ 20), maxMarks }`; `SeatAssignmentSchema` `{ id, tenantId, examPaperId, learnerId, roomId, seatLabel
   (1–10) }`; `HallTicketSchema` `{ id, tenantId, examId, learnerId, ticketNumber (1–40), issuedAt, revoked }`;
   `RevaluationRequestSchema` `{ id, tenantId, examPaperId, learnerId, reason (≤ 300), status (requested |
   in_review | changed | unchanged | rejected), oldMarks, newMarks (set iff changed), createdAt, updatedAt }`.
5. `records.ts` — `ReportCardSchema` `{ id, tenantId, learnerId, academicYearId, periodId (nullable), templateId,
   lines: (1–60) `{ subjectId, grade (1–8), marksPercent (0–100, nullable), remark (≤ 300, nullable) }`, overallRemark
   (≤ 1000, nullable), status (draft | approved | published | withdrawn), publishedAt (set iff published), createdAt,
   updatedAt }`.
6. `IssuedDocumentSchema` `{ id, tenantId, learnerId (nullable for staff letters), kind (bonafide | transfer |
   completion | character | transcript | letter | other), number (1–40), templateId, issuedOn, signatures: (0–5)
   `{ staffProfileId, signedAt, method (drawn | digital_certificate | otp) }`, verificationCode (`/^[A-Z0-9]{10,16}$/`),
   revoked, revokedReason (set iff revoked) }`. Doc comment: the public verification page shows only kind, number,
   issue date and validity — never personal data (V-7).
7. All objects `z.strictObject`; `updatedAt >= createdAt` (`Date.parse`); named exports and types; files ≤ 300
   lines; import `TimeOfDaySchema` from `notification.ts`.

## Acceptance checks
- [ ] Tests pass for: a CBSE-style letter scheme, a university GPA scheme, a rubric-marked project, an absent learner,
  an exam with two papers and seating, a changed revaluation, a published report card, a signed transfer certificate.
  They fail for: overlapping bands, `minPercent > maxPercent`, marks `12.25`, absent with marks, `end <= start`,
  `newMarks` without `changed`, published without `publishedAt`, a lower-case verification code, extra keys.
- [ ] `fnm exec --using=24 -- pnpm --dir frontend --filter @nexus/contracts test` and `… review:check` pass.
- [ ] Definition of done in `AGENTS.md` §9 (`CONTRACTS.md` rows; guides: none).
