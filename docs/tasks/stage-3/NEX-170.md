# NEX-170 — M21 Exams screens (schedule, seating plan, hall tickets, re-evaluation status)

**Status:** ready-for-review · **Owner:** Codex · **Branch:** task/NEX-170 · **Depends on:** NEX-158, NEX-169
**Requirements:** M21, O-1 (L2), V-7, G-6, D42, D71, D72, D75

## Goal
Staff see exams and their papers, view a paper's seating and generate a seating plan (online); guardians and learners
see only their own hall tickets and re-evaluation requests. Lists stay readable offline from the cache (L2 read).

## Build
1. `modules.ts`: `M21`, path `exams`, icon `ScrollText` (lucide), permission `null` (family viewers too; the handlers
   decide), `L2`, keys `m21.nav.title` / `m21.nav.summary`, lazy `../modules/m21/ExamsPage`.
2. `ExamsPage`: heading, intro, `LastSynced` (exams or hall-tickets query), tabs: Schedule and Seating only with
   `m21.exams.read`; Hall tickets & re-evaluation for everyone. 403 → existing no-access message.
3. `ScheduleTab`: exams (name, dates with tenant formatting, status badge with text); selecting an exam (`?exam=`)
   lists its papers: subject offering name (via `useSubjectOfferings()` / `useSubjects()`, absent → id hidden, show
   "Paper"), date, start–end, room names (`useRooms()`), max marks.
4. `SeatingTab`: exam + paper selects; seats grouped by room (room name, seat label, learner name via `useLearners()` +
   `usePeople()`, else learner number). "Generate seating plan" only with `m21.exams.manage`, disabled offline with
   text "Needs a connection"; confirm dialog says existing seats are replaced.
5. `POST /exam-papers/:id/seat-plan` (entitlement M21, `m21.exams.manage`, active staff profile, else 403): paper in the
   tenant (else 404); its exam status `planned` or `scheduled` (else 409 `conflict`, path `status`); learners = enrolled
   in the class group of the paper's subject offering on the paper `date` (logic as m17 `rosterFor`, sorted the same);
   rooms in `roomIds` order, each filled up to `capacity` (null capacity = unlimited); seat labels `<room letter
   index A, B, …><n>` (`A1`, `A2`, … ≤ 10 chars); not enough seats → 400 `invalid_request`, path `roomIds`, nothing
   changed. Replaces the paper's seat assignments; 200 with the page of `SeatAssignmentSchema`. Repeated
   `Idempotency-Key` in the tenant → the stored result. Errors carry paths only, never names or ids.
6. Service `useGenerateSeatPlan(paperId)`: online mutation (as `useRecordFeePayment` without the outbox, or the NEX-165
   hook), idempotency header, invalidates `queryKeys.m21.examSeats(scope, paperId)`.
7. `TicketsTab`: `useHallTickets()` — exam name, ticket number, issued date, "Revoked" text badge; learner name for
   staff and for guardians with more than one child. `useRevaluationRequests()` — paper, old / new marks, status badge
   with text; never show `reason` (V-7).
8. i18n en / hi / ta (D42); tokens only; files ≤ 300 lines; 360 px stacked, no horizontal scroll, RTL ok; touch targets
   ≥ 44 px; no names, marks, reasons or learner ids in console, errors or test names (V-7, G-6).
