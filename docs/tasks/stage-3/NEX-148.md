# NEX-148 — Contracts (M13, M14): learner records, enrolments, households, guardians, custody and pickup rights

**Status:** ready-for-review · **Owner:** Codex · **Branch:** task/NEX-148 · **Depends on:** NEX-146, NEX-147
**Requirements:** M13, M14, D25 (person vs. membership, temporal scoping), C-3, G-6, V-7, D72

## Goal
`@nexus/contracts` defines a learner's record and enrolment history, and the family around them: households, guardian
relationships with custody and pickup rights, and other people allowed to collect the child.

## Build
1. `learners.ts` — `LearnerStatusSchema` `enrolled | on_leave | withdrawn | transferred_out | graduated | alumni`;
   `HealthFlagSchema` `{ kind (allergy | medication | condition | dietary | accessibility | other), label (1–120),
   note (≤ 500, nullable) }`; `LearnerSchema` `{ id, tenantId, institutionId, campusId (nullable), personId (D25),
   roleProfileId (its `learner` RoleProfile), learnerNumber (1–40), admissionDate, status, leftOn (set iff withdrawn /
   transferred_out / graduated / alumni; not before admissionDate), healthFlags (≤ 20), customFields
   (`CustomFieldValuesSchema`), retentionState, createdAt, updatedAt }`. Doc comment: health flags and sensitive custom
   fields are personal data (V-7) — never in logs, offline only for permitted roles.
2. `EnrolmentSchema` `{ id, tenantId, learnerId, academicYearId, programId, yearLevelId (nullable), classGroupId,
   rollNumber (1–20, nullable), status (active | completed | withdrawn), effectiveFrom, effectiveTo (nullable, ≥ from;
   required unless active), createdAt, updatedAt }`.
3. `LearnerDocumentSchema` (metadata; the file is stored encrypted) `{ id, tenantId, learnerId, kind (birth_certificate
   | id_proof | transfer_certificate | photo | medical | previous_report | other), fileName (plain name, ≤ 200),
   contentType (pdf / jpeg / png / webp), sizeBytes (1 B – 20 MB), verified, verifiedByStaffProfileId (set iff
   verified), uploadedAt }`.
4. `families.ts` — `GuardianRelationshipSchema` `{ id, tenantId, guardianPersonId, learnerPersonId (≠ guardian), kind
   (mother | father | parent | step_parent | grandparent | legal_guardian | foster_carer | adult_sibling | other),
   parentalResponsibility, livesWithLearner, contactPriority (int 1–10), pickupRight (allowed | not_allowed |
   court_restricted), courtOrderNote (≤ 500, set iff court_restricted; personal data), effectiveFrom, effectiveTo
   (nullable, ≥ from), createdAt, updatedAt }`; export the two enums. Doc comment: extends the Stage 1 guardian link
   used for sign-in scoping (M02); the build step keeps them in step.
5. `HouseholdSchema` `{ id, tenantId, name, address (`AddressSchema` from `tenancy.ts`, nullable; a home address is
   personal data here — say so in a doc comment, V-7; do not edit `tenancy.ts`), learnerPersonIds (1–20, unique),
   guardianPersonIds (0–10, unique), primaryLanguage (`Locale`, nullable), createdAt, updatedAt }`;
   `AuthorisedPickupSchema` (non-guardians allowed to collect a learner) `{ id, tenantId, learnerPersonId, name, phone
   (`PhoneE164`), relationshipLabel (1–60), validFrom, validTo (nullable, ≥ from), addedByPersonId, createdAt }`.
6. Dates are `IsoDate`, instants `UtcDateTime`; all objects `z.strictObject`; `updatedAt >= createdAt` (`Date.parse`);
   named exports and types; files ≤ 300 lines.
