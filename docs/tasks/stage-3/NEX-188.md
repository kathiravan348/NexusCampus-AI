# NEX-188 — Build: DB + API for M18 fees and payments

**Status:** planned · **Owner:** — · **Branch:** task/NEX-188 · **Depends on:** NEX-184, NEX-205 (migration chain)
**Requirements:** M18, D9, G-6, V-1, V-2, V-7, O-2, D78, D80. Split (D83 planning): M19 accounting → NEX-206.

## Goal
Fee heads, plans, concessions, invoices, payments and refunds are stored per tenant under forced RLS and served by
the real backend with the same responses, errors, family scope and order as the mock. Recording a manual payment
applies it to the selected invoices atomically and is safe to replay from the offline outbox.

## Build
1. Migration `0033`: `fee_heads`, `fee_plans` (`lines`, `instalments` JSONB), `concessions`, `fee_invoices` (`lines`
   JSONB), `fee_payments` (`invoice_ids` varchar array 1–20, distinct), `fee_refunds`. Money as `bigint` minor units;
   currency `^[A-Z]{3}$`; CHECKs for every scalar contract rule (enums, ranges, `paid <= total`, status vs paid,
   `due_on >= issued_on`, decision fields iff decided, dates in order). Composite `(id, tenant_id)` references
   (institutions, calendars, programs, year levels, learners, people, staff profiles, plans, payments). Unique
   `(tenant_id, receipt_number)` and `(tenant_id, invoice_number)`. `concessions.reason` and `fee_refunds.reason` as
   FieldCipher text (`tenant_data`). ENABLE + FORCE RLS, `tenant_isolation`; `nexus_app` SELECT on all six, INSERT on
   `fee_payments`, `UPDATE (paid, status, updated_at)` on `fee_invoices` only.
2. Reads as the mock: heads, plans, concessions, refunds need `m18.fees.read` (insertion order). `GET /fee-invoices
   ?learnerId=&status=` and `GET /fee-payments?invoiceId=` (module only): with `m18.fees.read` everything; staff without
   it `403`; families only their learners (`403` if none); unknown or foreign learner / invoice filter `404`; a
   payment shows only when every invoice is visible. Decrypted concession / refund reasons are audited once per page
   (`m18.*.sensitiveRead`, field name only).
3. `POST /fee-payments` in the mock's order: module → `m18.fees.manage` → active staff profile (today) → body (`400`,
   path = first key, "Invalid fee payment") → each invoice open (`issued` / `part_paid`, else path `invoiceIds`) and
   same currency (path `currency`) → amount ≤ open balance (path `amount`) → payer = first invoice's learner person.
   Lock the invoices (`FOR UPDATE`), apply oldest due first, set `paid` / `status`; receipt `R-` + 6 digits, next per
   tenant under a transaction advisory lock; `pay-` id; `status: succeeded`; `deviceId` from the input. Audit
   `m18.feePayment.created` (field names only). `Idempotency-Key` replay comes from the core guard.
4. Tests (real DB): every read, filter, family scope and `403`; payment across two invoices (oldest first, statuses,
   receipt numbers in sequence); each `400` path; replay returns the same payment with one write and one audit row;
   reasons stored as ciphertext and in `ENCRYPTED_COLUMNS`; sensitive-read audit; tenant B isolation; forced RLS and
   grants (no other UPDATE); models match the schema.
