# NEX-150 — Contracts (M16, M17): rooms, timetable slots, teacher load; attendance sessions, marks, leave requests

**Status:** planned · **Owner:** — · **Branch:** task/NEX-150 · **Depends on:** NEX-146
**Requirements:** M16, M17, D25 (temporal scoping), G-3, V-7, D72

## Goal
`@nexus/contracts` defines rooms and the timetable (bell schedules, slots, teacher load) and attendance (sessions, one
mark per learner, leave requests) for every institution type — school periods, university lectures, coaching batches.

## Build
1. `timetable.ts` — `RoomKindSchema` `classroom | lab | hall | library | sports | online | other`; `RoomSchema` `{ id,
   tenantId, institutionId, campusId (nullable), code (`AcademicCodeSchema`), name, kind, capacity (int 1–5000,
   nullable), active, createdAt, updatedAt }`.
2. `BellScheduleSchema` `{ id, tenantId, institutionId, name, periods: array (1–20) of `{ code (AcademicCode), label
   (1–40), start, end (TimeOfDay, end > start), isBreak }` with no overlaps and ascending start, createdAt, updatedAt }`.
3. `TimetableSlotSchema` `{ id, tenantId, academicYearId, periodId (nullable), subjectOfferingId, weekday (int 1–7,
   ISO: 1 = Monday), start, end (TimeOfDay, end > start), roomId (nullable), staffProfileIds (unique, ≤ 10),
   effectiveFrom, effectiveTo (nullable, ≥ from), createdAt, updatedAt }`.
4. `TeacherLoadSchema` (read model) `{ staffProfileId, academicYearId, periodId (nullable), weeklyPeriods (int ≥ 0),
   weeklyMinutes (int ≥ 0), maxWeeklyPeriods (int ≥ 1, nullable), overloaded }`; refine: `overloaded` equals
   `maxWeeklyPeriods !== null && weeklyPeriods > maxWeeklyPeriods`.
5. Doc comment: room / teacher / class clashes are server checks, not schema rules.
6. `attendance.ts` — `AttendanceModeSchema` `daily | period | session | event`; `AttendanceMethodSchema` `manual | qr |
   nfc | biometric | geo | online_join`; `AttendanceSessionSchema` `{ id, tenantId, institutionId, mode, date
   (IsoDate), classGroupId (nullable), timetableSlotId (set iff mode = period), eventLabel (1–120, set iff mode =
   event), takenByStaffProfileId (nullable until taken), status (open | submitted | locked), submittedAt (set iff not
   open), createdAt, updatedAt }`.
7. `AttendanceStatusSchema` `present | absent | late | excused | on_leave | remote`; `AttendanceMarkSchema` `{ id,
   tenantId, sessionId, learnerId, status, method, minutesLate (int 1–600, set iff late), note (≤ 300, nullable;
   personal data), markedAt (UtcDateTime), markedByStaffProfileId (nullable for self check-in), deviceId
   (nullable — the `DeviceSync` device when marked offline, L2; marks merge `append-only`, `sync.ts`) }`.
8. `LeaveRequestSchema` `{ id, tenantId, learnerId, requestedByPersonId, from, to (IsoDate, to ≥ from), reason (1–500;
   personal data, never logged — V-7), status (pending | approved | rejected | cancelled), decidedByStaffProfileId and
   decidedAt (both set iff approved / rejected), createdAt, updatedAt }`.
9. Biometric and geo methods store only the result, never templates or coordinates — doc comment (V-7).
10. Dates `IsoDate`, instants `UtcDateTime`; all objects `z.strictObject`; `updatedAt >= createdAt` (`Date.parse`);
    named exports and types; files ≤ 300 lines; import `TimeOfDaySchema` from `notification.ts`, do not copy it.
