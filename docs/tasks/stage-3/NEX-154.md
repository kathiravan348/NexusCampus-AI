# NEX-154 — Fixtures: academic structure, learners and families for the 5 demo tenants and the Group

**Status:** planned · **Owner:** — · **Branch:** task/NEX-154 · **Depends on:** NEX-146, NEX-147, NEX-148
**Requirements:** M15, M08, M13, M14, D16, G-3, G-6, V-7, D72, D75

## Goal
`@nexus/mocks` has demo data in the Stage 3 contract shapes for every demo tenant (Little Steps EY, Riverside K12
group with 2 campuses, Northbridge HE, Apex TP, Harmony SK): programs to subject offerings, learner records and
enrolments, households, guardian relationships, authorised pickups, and M08 fields / forms / workflows / numbering.

## Build
1. `ids-stage3.ts`: every new id as a named constant (D16 style: `PROGRAM`, `YEAR_LEVEL`, `CLASS_GROUP`, `SUBJECT`,
   `OFFERING`, `LEARNER`, `HOUSEHOLD`, …); other files use these, never id literals. Use existing `TENANT`,
   `INSTITUTION`, `CAMPUS`, `PERSON`, `CALENDAR` (the calendar id is the `academicYearId`, as in `role-profiles.ts`).
2. `academics.ts`: `PROGRAMS`, `YEAR_LEVELS`, `CLASS_GROUPS`, `SUBJECTS`, `SUBJECT_OFFERINGS` — per tenant 1–2
   programs, 2–4 year levels, 2–4 class groups (Riverside: at least one per campus), 4–6 subjects and an offering per
   class group × 2 subjects with a staff profile id of that tenant. Words fit the type (EY room / K12 section / HE
   cohort / TP batch / SK group) via `ClassGroupKind`.
3. `learner-records.ts`: `LEARNERS` (one per learner role profile in `ROLE_PROFILES`, `roleProfileId` matching,
   `customFields` only keys defined in `config.ts`), `ENROLMENTS` (one active per learner, class group of the same
   tenant), `LEARNER_DOCUMENTS` (≥ 1 per tenant, metadata only). At least one learner has a health flag (restricted).
4. `families.ts`: `HOUSEHOLDS` (every learner in exactly one household of its tenant), `GUARDIAN_RELATIONSHIPS` (one
   per row of `GUARDIAN_LINKS`, same people), `AUTHORISED_PICKUPS` (≥ 1 per tenant). Riverside has one
   `court_restricted` relationship with a `courtOrderNote`. Phones are fictional, in the ranges `people.ts` already
   uses (`+447700900…`, `+1202555010…`, `+658000010…`; India: the same pattern as the `ls` / `ax` people there).
   Staff profile ids are the `rp-…-staff` ids from `ROLE_PROFILES`.
5. `config.ts`: `CUSTOM_FIELD_DEFINITIONS` (≥ 2 per tenant, one `sensitive`), `FORM_DEFINITIONS` (≥ 1 per tenant,
   only fields defined here), `WORKFLOW_DEFINITIONS` (≥ 1 per tenant), `NUMBERING_FORMATS` (learner number per
   tenant; `LEARNERS.learnerNumber` follows it).
6. Use `CREATED_AT` / `UPDATED_AT` from `tenants.ts`; dates inside each tenant's calendar year. Files ≤ 300 lines.
7. D75: these sets are exported from `fixtures/index.ts` for MSW only — do **not** add them to `demoFixtures()`,
   do not bump `DEMO_FIXTURES_VERSION`, do not touch `backend/`.
