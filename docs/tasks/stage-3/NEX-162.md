## Goal
In demo mode the campus app has an "Import data" screen: past import jobs, a job view with its column mappings and
dry-run issues, a "New import" step that registers a file, and the Assist (M11) helper. No file contents leave the device.

## Build
1. `modules.ts`: `M09`, path `import`, icon `FileUp` (lucide), permission `m09.import.read`, `L0` (the
   guard already shows the offline notice), keys `m09.nav.title` / `m09.nav.summary`, lazy `../modules/m09/ImportsPage`.
2. `ImportsPage`: heading, intro, "Ask Assist" button (as `StructurePage`), jobs list (file name, entity, status
   badge with text, valid / error / total rows, `createdAt` in the tenant's time zone); selecting one opens
   `ImportJobView` (`?job=` search param). Empty / error states; 360 px usable (stacked cards).
3. `ImportJobView`: status, counts, rollback deadline when `completed`; mappings (`useImportJobMappings`: column →
   field, transform); issues (`useImportJobIssues`: row, column, severity, text from `messageKey` — never cell values).
4. Write: `ImportJobInputSchema` = `{ entity, fileName, sourceFormat }` (reuse the job's `fileName` rule — move it to
   a named const). `POST /import-jobs` (entitlement M09, permission `m09.import.manage`) creates a job with status
   `uploaded`, zero rows, `templateVersion: 1`, `rollbackUntil: null`, `createdByStaffProfileId` = the viewer's staff
   profile (no staff profile → 403); 201 with the job. Hook `useCreateImportJob()` invalidates the M09 keys.
5. `NewImportDialog`: entity select, file picker (`.csv,.xlsx`; the format comes from the extension, anything else
   → field error); sends **only** the file name, entity and format — the file is not read or uploaded (D75: parsing
   is backend work; the dialog text says so). Shown only with `m09.import.manage`.
6. i18n en / hi / ta (D42) — including every `m09.import.*` issue `messageKey` used in the fixtures; tokens only;
   files ≤ 300 lines; no file names or cell values in console, errors or test names (G-6, V-7).
