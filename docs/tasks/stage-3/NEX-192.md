## Build
1. `GET /me/home` (module `M28`, any signed-in user of the tenant): no role profile → `403`. With
   `m28.dashboards.read` → `leader` home (KPI count card, pending-leave alert card). Else a staff profile → `staff`
   home (today's sessions taken by them, on their slots or of their homeroom groups; pending leave of learners in
   their homeroom / offering groups; communication cards). Else guardian → `family`, learner → `learner` (absences
   this week Monday to today in the tenant's time zone; invoices with an open balance; communication cards); any
   other profile → `403`. Communication cards only when M24 is on: unread messages in non-archived threads (with
   `m24.messages.read`) and visible notices (with `m24.notices.read`).
2. `GET /dashboards/kpis` (`m28.dashboards.read`): attendance percent, fees collected and outstanding in the
   tenant's currency (non-draft, non-void invoices), open applications, active learners — as the mock, a plain array.
3. The tenant's time zone and currency come from its first institution by id. Cards use the mock's message keys and
   hrefs. Responses validate against `homes.ts`.
4. Tests (real DB): each role's home and counts (absences inside / outside this week, open balances, unread
   messages, sessions, pending leave), M24 off removes communication cards, no profile `403`, KPIs values and
   permission, tenant B isolation (counts never include another tenant's rows).
