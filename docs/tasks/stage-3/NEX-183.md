## Build
1. Migration `0024`: tables `programs`, `year_levels`, `class_groups`, `subjects`, `subject_offerings`, columns as
   the contract (snake_case), `tenant_id` on every table, FKs to `institutions`, `campuses`, `academic_calendars`,
   `role_profiles`; `staff_profile_ids` as an array (max 10, no duplicates). Unique: program/subject `code` per
   institution, year level `code` per program and `order` per program, class group `code` per academic year.
   Every table: ENABLE + FORCE RLS with the `tenant_isolation` policy and `nexus_app` grants as in `0010`.
2. Routes (prefix `/api/v1`, module `M15`): `GET /programs`, `/year-levels`, `/class-groups`, `/subjects`
   (`m15.structure.read`, paged like `nexus.core.pagination`), `GET /subject-offerings?academicYearId=` (unknown or
   other tenant's year → `404`), `POST /class-groups` (`m15.structure.manage`) with the mock's checks and order:
   `400 invalid_request` with `details[].path` for bad body or a referenced id outside the tenant or a year level
   not in the program, `409 conflict` for a duplicate code in the same academic year; `201` returns the stored row.
3. `POST /class-groups` writes audit `m15.class_group.created` (field names only, no values) in the same
   transaction. Ids from `nexus.core.ids` with the mock's prefixes.
4. Stage 3 access goes real (D80): export `STAGE3_PERMISSIONS`, the Stage 3 system-role grants and
   `STAGE3_ENTITLEMENTS` with the demo fixtures (`export.ts`; `db.ts` must not add them twice), add the same codes
   to `CATALOGUE`, insert the permission rows in a migration and the grants / entitlements where `seed/rbac.py`
   seeds Stage 1's. The parity test (`tests/db/test_permissions.py`) stays as is and passes. No Stage 3 data rows.
5. Tests (real database, as `tests/db/m03`): each route happy path; paging; teacher without manage → `403`;
   module switched off → `403`; tenant B cannot read or reference tenant A rows (`404` / `400`); duplicate code
   `409`; year level from another program `400`; audit row written; models match the migrated schema.
