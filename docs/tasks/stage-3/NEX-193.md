# NEX-193 — Build: M86 rollover backend (dry run, decisions, confirm, roll-back window, audit)

**Status:** planned · **Owner:** — · **Branch:** task/NEX-193 · **Depends on:** NEX-208 (contract), NEX-191 (migration chain)
**Requirements:** M86, D76, D78 (Owner review point 3), D84, V-1, V-2, V-7

## Goal
Rollover runs and promotion decisions are stored per tenant under forced RLS; the reads and the D84 write flow run on
the real backend with the same responses and errors as the NEX-208 mock. Confirm and roll back move enrolments and
learner statuses in one transaction each and are fully reversible inside the 14-day window.

## Build
1. Migration `0039`: `rollover_runs` (counts as five integer columns, partial unique index for one open run per
   tenant, institution and from-year), `promotion_decisions` (plus internal `previous_enrolment_id`,
   `new_enrolment_id`, `previous_learner_status`, never returned). CHECKs for the contract rules. ENABLE + FORCE RLS,
   `tenant_isolation`; `nexus_app`: SELECT, INSERT and status / count / window updates on the two tables;
   `INSERT, DELETE, UPDATE (status, effective_to, updated_at)` on `enrolments`; `UPDATE (status, updated_at)` on
   `learners` (D84).
2. Reads: `GET /rollover-runs`, `/rollover-runs/:id/decisions` (`m86.rollover.read`, `404` unknown).
3. Writes in the NEX-208 order and errors (D84 rules). Audit `m86.rolloverRun.created`, `…decisionOverridden`,
   `…confirmed`, `…rolledBack` (counts or field names only, never learner names).
4. Tests (real DB): dry run decisions for promote, graduate, both skip reasons; override and recount; confirm moves
   enrolments and statuses; roll back restores them exactly; window expiry `409`; one open run `409`; guard order;
   tenant B isolation; forced RLS and grants; models match the schema.
