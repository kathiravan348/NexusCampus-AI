## Build
1. `modules.ts`: `M24`, path `messages`, icon `MessagesSquare` (lucide), permission `null` (the handlers decide),
   `L2`, keys `m24.nav.title` / `m24.nav.summary`, lazy `../modules/m24/MessagesPage`.
2. `MessagesPage`: heading, intro, `LastSynced` (threads query); tabs Messages (`m24.messages.read`), Notices
   (`m24.notices.read`), Meetings (`m24.meetings.read`) — a tab shows only with its permission; none → no-access message.
3. `ThreadList`: subject, kind as text (`m24.kind.<kind>`, 4 kinds), last message date (tenant formatting), "Archived"
   badge; newest first. `?thread=` opens `ThreadView`.
4. `ThreadView`: messages oldest first; sender name via `usePeople()` (else "Member"), sent time, "Edited" text,
   "You" for the viewer's own. Reply box only with `m24.messages.send` and not on archived threads: textarea
   (required, ≤ 4000, counter). Queued replies show at the end with a "Waiting to send" badge; failed → "Not sent".
5. Contract: `ThreadMessageInputSchema` = strict `{ body }`, same bounds as `ThreadMessageSchema.body` (trim, 1…4000).
6. `POST /message-threads/:id/messages` (entitlement M24, `m24.messages.send`, else 403): thread among the viewer's
   threads (`viewerThreads`, else 404); archived → 409 `conflict`, path `archived`; invalid body → 400
   `invalid_request`, path `body`. Adds the message (sender = viewer, `readByPersonIds` = [sender], `deviceId`
   null as m17), sets the thread's `lastMessageAt`; 201 with `ThreadMessageSchema`. Repeated
   `Idempotency-Key` in the tenant → the stored result. Errors carry paths only, never the body or names.
7. Service `useSendThreadMessage(threadId)`: `useOutboxMutation` (as `useSaveAttendanceMark`, without its session
   checks beyond tenant / user): module `M24`, operation `messages.send`, merge `append-only`, priority `normal`;
   invalidates `queryKeys.m24.threadMessages(scope, threadId)` and `messageThreads` on success.
8. `NoticesTab`: title, publish date, body (plain text, no HTML), "Needs acknowledgement" badge; with `m24.notices.publish` also status badge.
9. `MeetingsTab`: bookings with slot date / start–end (`useMeetingSlots()`), mode as text, location, learner name
   (`useLearners()` + `usePeople()`, else learner number), status badge with text. Never show `note` (V-7).
10. i18n en / hi / ta (D42); tokens only; files ≤ 300 lines; 360 px stacked, RTL ok; touch targets ≥ 44 px; no
    message bodies, notes, names or ids in console, errors or test names (V-7, G-6).
