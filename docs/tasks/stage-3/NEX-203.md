## Build
1. Migration `0030`: `import_jobs` (columns as `ImportJob`, snake_case; `created_by_staff_profile_id` with a composite
   `(id, tenant_id)` reference to `role_profiles`), `column_mappings` (`job_id` primary key, `tenant_id`, `columns`
   JSONB), `import_row_issues` (`id`, `tenant_id`, `job_id`, `row_number`, `column`, `severity`, `code`,
   `message_key`). Mappings and issues reference `(job_id, tenant_id)` → `import_jobs (id, tenant_id)`. CHECKs for
   the contract: enums, plain file name (1–200, no `/ : \`, no control characters, not `.` / `..`),
   `template_version >= 1`, row counts ≥ 0 and `valid_rows + error_rows <= total_rows`, `rollback_until` set exactly
   when `completed`, `updated_at >= created_at`, issue `row_number >= 1`, `code ~ '^[a-z_]{3,40}$'`, `columns` an
   array of 1–200. ENABLE + FORCE RLS, `tenant_isolation`, `nexus_app`: SELECT on all three, INSERT on `import_jobs` only.
2. Routes (module `M09`): `GET /import-jobs` (`m09.import.read`, paged, by `created_at`, `id`);
   `GET /import-jobs/:id/mappings` and `/issues` (`m09.import.read`, paged; job of another tenant or unknown → `404`;
   issues ordered by `row_number`, `id`). Rows are validated against the schemas on the way out (`500` if stored data
   breaks the contract, as M14).
3. `POST /import-jobs` in the mock's order: module → `m09.import.manage` → viewer's active staff role profile (none →
   `403 forbidden`) → body (`400 invalid_request`, bad JSON path `""`, extra fields rejected) → insert with an `imp-`
   id from `nexus.core.ids`, `status: uploaded`, zero rows, `template_version: 1`, `rollback_until: null` → `201`.
   Audit `m09.importJob.created` (field names only — never the file name) in the same transaction.
4. Tests (real DB, as `tests/db/m14`): list / mappings / issues paging and order; other tenant's job `404`; create
   happy path and stored row; no permission / no active staff profile `403`; bad JSON, unsafe file name, unknown
   entity, extra field `400`; audit has no file name; tenant B isolation; forced RLS on all three tables;
   `nexus_app` cannot update or delete; models match the schema.
