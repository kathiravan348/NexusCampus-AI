## Build
1. Migration `0031`: `rooms`, `bell_schedules` (`periods` JSONB array 1–20), `timetable_slots` (`staff_profile_ids`
   varchar array ≤ 10, distinct). Columns as the contract (snake_case); composite `(id, tenant_id)` references to
   institutions, campuses, academic calendars, subject offerings, rooms. CHECKs: room kind enum, capacity 1–5000,
   weekday 1–7, `end > start` (`HH:MM` text), `effective_to >= effective_from`, `updated_at >= created_at`. ENABLE +
   FORCE RLS, `tenant_isolation`; `nexus_app` SELECT on all three, INSERT on `timetable_slots` only.
2. `GET /rooms`, `/bell-schedules` (module `M16`, `m16.timetable.read`, paged, insertion order).
3. `GET /timetable-slots?classGroupId=&staffProfileId=`: unknown class group or staff profile → `404`; staff
   viewers see all slots; others only slots of offerings whose class group holds an active enrolment of a learner
   in their family (`family_scope`).
4. `POST /timetable-slots` in the mock's order: module → `m16.timetable.manage` → body (`400`, detail paths = input
   keys only, message "Invalid timetable slot field") → reference checks with the mock's paths and messages →
   clashes `409 conflict` (room, then staff, then class group; same weekday, overlapping times and dates) → insert
   `tts-` id → `201`. Audit `m16.timetableSlot.created` (field names only).
5. `GET /teacher-load?academicYearId=`: non-staff viewer → `403 forbidden`; unknown year → `404`; computed per
   (staff profile, year, period) exactly as `teacherLoads()` (`maxWeeklyPeriods: null`, `overloaded: false`).
6. Tests (real DB): lists and paging; slot filters and `404`s; guardian sees only their child's class slots;
   create happy path + audit; each `400` path; each `409`; guard before body; `module_disabled`; teacher load sums
   and staff-only; tenant B isolation; forced RLS + grants on all three; models match the schema.
