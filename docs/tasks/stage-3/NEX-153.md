# NEX-153 — Contracts (M24–M28, M86): messages, notices, meetings; portal homes; dashboards; rollover runs

## Goal
`@nexus/contracts` defines school communication (threads, notices, parent–teacher meetings), the role home pages of
the family / learner / staff portals and dashboards, and the year-end rollover run with per-learner decisions.

## Build
1. `communication.ts` — `MessageThreadSchema` `{ id, tenantId, institutionId, kind (direct | class_group | staff_group
   | broadcast), subject (1–160), participantPersonIds (2–500, unique; broadcast may be 1), classGroupId (set iff
   class_group), lastMessageAt (nullable), archived, createdAt, updatedAt }`; `ThreadMessageSchema` `{ id, tenantId,
   threadId, senderPersonId, body (1–4000; personal data, never logged), attachmentIds (unique, ≤ 10), sentAt,
   editedAt (nullable, ≥ sentAt), readByPersonIds (unique), deviceId (nullable, offline L2) }`.
2. `NoticeSchema` `{ id, tenantId, institutionId, title (1–160), body (1–8000), audience: `{ kind (everyone |
   class_groups | roles | people), ids (unique, ≤ 500; empty iff everyone) }`, channels (1–5 unique `ChannelSchema`),
   requiresAcknowledgement, publishAt, expiresAt (nullable, > publishAt), status (draft | scheduled | published |
   withdrawn), createdByStaffProfileId, createdAt, updatedAt }`.
3. `MeetingSlotSchema` (PTM) `{ id, tenantId, staffProfileId, date, start, end (TimeOfDay, end > start), mode
   (in_person | video | phone), location (≤ 120, nullable), capacity (int 1–10) }`; `MeetingBookingSchema` `{ id,
   tenantId, slotId, guardianPersonId, learnerId, status (booked | cancelled | attended | no_show), note (≤ 300,
   nullable; personal data), createdAt, updatedAt }`.
4. `homes.ts` — `HomeCardKindSchema` `attendance | fees | results | timetable | messages | notices | consents | pickups
   | leave | payslips | tasks | kpi | alerts`; `HomeCardSchema` `{ kind, titleKey (`MessageKeySchema`), moduleId
   (`ModuleIdSchema`), count (int ≥ 0, nullable), severity (info | warning | critical, nullable), href (app path
   `/^\/[a-z0-9\-/]*$/`) }`; `RoleHomeSchema` `{ role (family | learner | staff | leader), personId, learnerIds (unique,
   ≤ 10; the child switcher; empty for staff / leader), cards (1–24), generatedAt }`.
5. `KpiSchema` `{ code (`/^[a-z][a-z0-9_]{2,39}$/`), labelKey (MessageKey), value (number), unit (count | percent |
   minor_units | days), currency (set iff minor_units), trend (up | down | flat, nullable), asOf }`;
   `SavedViewSchema` `{ id, tenantId, ownerPersonId, moduleId, name (1–80), filters (record string → string, ≤ 20
   keys), createdAt }`. Doc comment: home cards and KPIs carry counts and aggregates only, never other people's
   personal data (G-6, V-7).
6. `rollover.ts` — `RolloverRunSchema` `{ id, tenantId, institutionId, fromAcademicYearId, toAcademicYearId (≠ from),
   status (draft | dry_run_ready | running | completed | rolled_back | failed), counts: `{ promote, detain, graduate,
   transfer, skip }` (ints ≥ 0), carryForwardFees, rollbackUntil (set iff completed), createdByStaffProfileId,
   createdAt, updatedAt }`; `PromotionDecisionSchema` `{ id, tenantId, runId, learnerId, action (promote | detain |
   graduate | transfer | skip), toClassGroupId (set iff promote or detain), reasonKey (MessageKey, nullable),
   overriddenByStaffProfileId (nullable) }`.
7. All objects `z.strictObject`; `updatedAt >= createdAt` (`Date.parse`); named exports and types; files ≤ 300 lines;
   before naming a schema check that `index.ts` does not already export the name (Stage 2 `control/` is re-exported).
