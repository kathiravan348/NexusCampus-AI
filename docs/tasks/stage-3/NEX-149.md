# NEX-149 — Contracts (M12, M09): enquiries, applications, offers, waitlist; import jobs and column mappings

**Status:** planned · **Owner:** — · **Branch:** task/NEX-149 · **Depends on:** NEX-148
**Requirements:** M12, M09, C-3, V-7, D72

## Goal
`@nexus/contracts` defines the admissions funnel (enquiry → application → offer → enrolment, with a waitlist) and the
import toolkit (templates, column mapping, dry run, rollback) used to bring records in from spreadsheets or old systems.

## Build
1. `admissions.ts` — `EnquirySourceSchema` `walk_in | phone | website | public_form | referral | campaign | event |
   other`; `EnquirySchema` `{ id, tenantId, institutionId, campusId (nullable), source, campaignCode (AcademicCode,
   nullable), contactName (NameSchema), contactPhone (PhoneE164, nullable), contactEmail (EmailSchema, nullable; at
   least one of phone / email), learnerName, programId (nullable), status (new | contacted | visit_booked | applied |
   lost), lostReason (≤ 300, set iff lost), assignedStaffProfileId (nullable), followUpOn (IsoDate, nullable),
   createdAt, updatedAt }`. Doc comment: contact details are personal data (V-7); a lead score is advisory, a person
   decides.
2. `ApplicationStatusSchema` `draft | submitted | under_review | test_scheduled | offered | waitlisted | accepted |
   rejected | withdrawn | enrolled`; `ApplicationSchema` `{ id, tenantId, institutionId, enquiryId (nullable),
   applicationNumber (1–40, from the `application` numbering format), formId (a `FormDefinition` id), academicYearId,
   programId, yearLevelId (nullable), applicantPersonId, guardianPersonIds (unique, ≤ 4), answers
   (`CustomFieldValuesSchema`), documentIds (unique, ≤ 30), status, submittedAt (set iff status ≠ draft), decidedAt
   (set iff offered / waitlisted / rejected / accepted / enrolled), createdAt, updatedAt }`.
3. `AdmissionOfferSchema` `{ id, tenantId, applicationId, classGroupId (nullable), expiresOn (IsoDate), status (open |
   accepted | declined | expired | revoked), respondedAt (set iff accepted / declined), createdAt }`;
   `WaitlistEntrySchema` `{ id, tenantId, applicationId, programId, position (int ≥ 1), addedAt }`.
4. `imports.ts` — `ImportEntitySchema` `learner | guardian | staff | enrolment | fee_balance | mark`; `ImportJobSchema`
   `{ id, tenantId, entity, fileName (plain name ≤ 200, no path), sourceFormat (csv | xlsx), templateVersion (int ≥ 1),
   status (uploaded | mapped | dry_run_ready | importing | completed | failed | rolled_back), totalRows, validRows,
   errorRows (ints ≥ 0, valid + error ≤ total), createdByStaffProfileId, rollbackUntil (UtcDateTime, set iff
   completed), createdAt, updatedAt }`.
5. `ColumnMappingSchema` `{ jobId, columns: array (1–200) of `{ sourceHeader (1–120), target (a dotted field path
   `/^[a-z][a-zA-Z0-9]*(\.[a-z][a-zA-Z0-9]*)?$/` or `custom:<CustomFieldKey>`, nullable = skip), transform (none | trim
   | upper | lower | date_dmy | date_mdy | phone_in | split_name) }`, targets unique when set }`.
6. `ImportRowIssueSchema` `{ rowNumber (int ≥ 1), column (1–120, nullable), severity (error | warning), code
   (`/^[a-z_]{3,40}$/`), messageKey (text key `/^[a-z][a-zA-Z0-9]*(\.[a-zA-Z0-9_]+)+$/`, never the cell value — V-7) }`; `DryRunReportSchema` `{ jobId,
   issues (≤ 1000), truncated (boolean), wouldCreate, wouldUpdate (ints ≥ 0) }`.
7. All objects `z.strictObject`; `updatedAt >= createdAt` (`Date.parse`); named exports and types; files ≤ 300 lines.
