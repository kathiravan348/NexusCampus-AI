## Build
1. Contract: `RolloverRunInputSchema` (strict: `institutionId`, `fromAcademicYearId`, `toAcademicYearId`,
   `carryForwardFees`; years differ) and `PromotionDecisionInputSchema` (strict: `action`, `toClassGroupId`,
   `reasonKey`; target iff promote / detain). Tests for both.
2. Mock (module `M86`, `m86.rollover.manage`, active staff profile, in that order; then body, then state):
   - `POST /rollover-runs` → `201 RolloverRun` `dry_run_ready` with decisions by the D84 rules; an open run for the
     same institution and from-year → `409` path `fromAcademicYearId`; unknown institution / year → `400` with path.
   - `PUT /rollover-runs/:id/decisions/:decisionId` → `200 PromotionDecision` (overridden by the viewer's staff
     profile); run not `dry_run_ready` → `409` path `status`; target group not in the to-year → `400` path
     `toClassGroupId`. Counts are recomputed.
   - `POST /rollover-runs/:id/confirm` → `200` `completed`, `rollbackUntil` = now + 14 days (mock does not move
     enrolments); `POST …/rollback` → `200` `rolled_back` inside the window, else `409` path `rollbackUntil`.
   - Unknown run or decision → `404`.
3. Mock tests for every route, error and order; existing rollover read tests stay green.
