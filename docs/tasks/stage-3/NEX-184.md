# NEX-184 — Build: DB + API for M13 learner records

**Status:** planned · **Owner:** — · **Branch:** task/NEX-184 · **Depends on:** NEX-200
**Requirements:** M13, G-6 (minors' privacy), V-1, V-2, V-7, E-3 (sensitive reads audited), ARCHITECTURE §10, D78, D80

## Goal
Learners, enrolments and learner document metadata are stored per tenant under forced RLS, health flags and
sensitive custom field values are field-encrypted, and the API returns exactly what the mock returns to each viewer.

## Build
1. Migration: `learners`, `enrolments`, `learner_documents` (metadata only), columns as the contract, composite
   `(id, tenant_id)` references (people, role profiles, campuses, academic years, programs, year levels, class
   groups); `health_flags` and sensitive custom field values stored only as `FieldCipher` text bound to their
   column; other custom fields as JSONB. ENABLE + FORCE RLS, `tenant_isolation`, `nexus_app` SELECT only.
2. Routes (module `M13`): `GET /learners`, `/learners/{id}`, `/learners/{id}/enrolments`, `/learners/{id}/documents`.
   Access as the mock: `m13.learner.read` sees all; otherwise only learners whose person is in the viewer's family
   (`family_of`), none → `403`; another tenant's or out-of-scope id → `404`. Masking as the mock: without
   `m13.learner.read_restricted` and not family → `healthFlags: []` and sensitive custom fields (M08 definitions with
   `sensitive`) removed — never decrypted for that viewer.
3. E-3: when unmasked health flags or sensitive custom fields are returned to a viewer who is not family, record
   one audit event per request, `m13.learner.sensitiveRead` (target learner id, or `learnerList`; field names only,
   no values), in the request transaction.
4. Register the encrypted columns in `ENCRYPTED_COLUMNS` so a tenant export carries readable values.
5. Tests (real DB, as `tests/db/m15`): each route; paging; staff vs teacher vs guardian (own child only, other child
   `404`); masking with and without restricted access; ciphertext in the table, plaintext only in allowed responses;
   audit only when sensitive data is shown; tenant B isolation; forced RLS; a tenant export test row decrypts.
