# NEX-151 — Contracts (M18, M19): fee plans, instalments, concessions, invoices, payments, refunds; ledger and budgets

**Status:** planned · **Owner:** — · **Branch:** task/NEX-151 · **Depends on:** NEX-148
**Requirements:** M18, M19, D9 (money in minor units with a currency), V-7, D72

## Goal
`@nexus/contracts` defines what a family is charged and pays (fee plans, instalments, concessions, invoices,
payments, refunds) and the institution's books (accounts, journal entries, budgets) — one shape for every country.

## Build
1. Money: every amount is `MinorUnitsSchema` (int) next to a `currency` (`CurrencyCodeSchema`); amounts ≥ 0 unless
   stated; never floats. One currency per record.
2. `fees.ts` — `FeeHeadSchema` `{ id, tenantId, institutionId, code (AcademicCode), name, taxRateBasisPoints (int
   0–10000), refundable, active }`; `FeePlanSchema` `{ id, tenantId, institutionId, academicYearId, programId
   (nullable), yearLevelId (nullable), name, currency, lines: (1–30) `{ feeHeadId, amount }` (unique fee heads),
   instalments: (1–24) `{ code, dueOn (IsoDate, ascending), sharePercentBasisPoints (int 1–10000) }` summing to 10000,
   createdAt, updatedAt }`.
3. `ConcessionSchema` `{ id, tenantId, learnerId, feePlanId, kind (sibling | merit | need_based | staff_child |
   scholarship | award_credit | other), mode (percent | fixed), value (int: basis points 1–10000 for percent, minor
   units ≥ 1 for fixed), reason (≤ 300, personal data), approvedByStaffProfileId (nullable), validFrom, validTo
   (nullable, ≥ from), createdAt }`.
4. `FeeInvoiceSchema` (lines: exported `FeeInvoiceLineSchema`; status: `FeeInvoiceStatusSchema`) `{ id, tenantId, learnerId, invoiceNumber (1–40), currency, issuedOn, dueOn (≥ issuedOn), lines:
   (1–50) `{ feeHeadId, description (1–120), amount, discount (≤ amount), tax }`, total (= Σ amount − discount +
   tax), paid (0–total), status (draft | issued | part_paid | paid | void | written_off), createdAt, updatedAt }`;
   refine the total and that `status` agrees with `paid` for `issued` / `part_paid` / `paid`.
5. `FeePaymentSchema` (`FeePaymentMethodSchema`, `FeePaymentStatusSchema`) `{ id, tenantId, invoiceIds (1–20, unique), payerPersonId, currency, amount (≥ 1), method (cash |
   cheque | bank_transfer | card | upi | wallet | gateway), gatewayReference (≤ 120, nullable; never card data —
   doc comment), receiptNumber (1–40), receivedAt (UtcDateTime), status (pending | succeeded | failed | reversed),
   deviceId (nullable — taken offline, L2) }`; `FeeRefundSchema` `{ id, tenantId, paymentId, amount (≥ 1), reason (≤ 300),
   status (requested | approved | paid | rejected), decidedByStaffProfileId and decidedAt (set iff not requested),
   createdAt }`.
6. `accounting.ts` — `LedgerAccountSchema` `{ id, tenantId, institutionId, code (`/^\d{3,10}$/`), name, kind (asset |
   liability | equity | income | expense), parentId (nullable), active }`; `JournalEntrySchema` `{ id, tenantId,
   institutionId, postedOn, reference (≤ 60), currency, lines: (2–100) `{ accountId, debit, credit }` with exactly one
   of debit / credit > 0 per line and Σ debit = Σ credit, source (manual | fees | payroll | import), createdAt }`;
   `BudgetSchema` `{ id, tenantId, institutionId, academicYearId, currency, lines: (1–200) `{ accountId (unique),
   amount }`, status (draft | approved | closed), createdAt, updatedAt }`.
7. Doc comment: country tax rules, bank reconciliation and ERP export are server / later work.
8. Names: Stage 2 `control/billing.ts` already exports `Invoice*` / `Payment*` (re-exported from `index.ts`), so the
   M18 names carry the `Fee` prefix; never edit `control/`. All objects `z.strictObject`; `updatedAt >= createdAt` (`Date.parse`); named exports and types; files ≤ 300 lines.
