## Goal
Grading schemes, assessments, rubrics and mark entries are stored per tenant under forced RLS and served by the real
backend with the same responses, errors, family scope and order as the mock. Mark entry is an upsert per assessment
and learner, safe to replay from the offline outbox. Remarks are personal data: encrypted, never logged.

## Build
1. Migration `0035`: `grading_schemes` (`bands` JSONB 1–20), `assessments` (`max_marks` and `weight_percent` numeric,
   max marks 1–1000 in halves, weight 0–100), `rubrics` (`criteria` JSONB 1–20), `mark_entries` (marks numeric ≥ 0 in
   halves or null, `absent`, `rubric_scores` JSONB or null, encrypted `remark`, staff profile, `entered_at`, device;
   unique `(tenant_id, assessment_id, learner_id)`; `absent` ⇒ marks null). Composite `(id, tenant_id)` references
   (institutions, subject offerings, rubrics, learners, staff profiles). ENABLE + FORCE RLS, `tenant_isolation`;
   `nexus_app` SELECT on all four; INSERT and UPDATE of the entry columns on `mark_entries` only.
2. Reads as the mock: schemes, rubrics, `GET /assessments?classGroupId=` (unknown group `404`) and `/:id/roster`
   (today's placements, roll number order) need `m20.marks.read`; `GET /assessments/:id/marks` (module only): with read
   all entries and remarks (one `m20.markEntry.sensitiveRead` per page that shows a remark); families only published
   assessments (else `404`), their learners, remark null; staff without read and empty families `403`.
3. `PUT /assessments/:id/marks/:learnerId` in the mock's order: module → `m20.marks.enter` → active staff profile
   (today) → assessment `404` → status `open` / `marking` else `409` path `status` → body `400` (first key, "Invalid
   mark entry") → roster (path `learnerId`) → marks ≤ max (path `marks`) → rubric rules (path `rubricScores`, the
   mock's three messages) → upsert (keep the id) → `200`. Audit `m20.markEntry.saved` (field names; `remark` marked
   sensitive). Replay comes from the core `Idempotency-Key` guard.
4. Tests (real DB): lists, filters, roster, family scope and masking, sensitive-read audit; create then update keeps
   the id; each `400` / `409`; replay; remark ciphertext and `ENCRYPTED_COLUMNS`; tenant B isolation; forced RLS and
   grants; models match the schema.
