## Build
1. Migration `0034`: `ledger_accounts` (code `^[0-9]{3,10}$` unique per institution, optional parent in the same
   tenant, `parent_id <> id`), `journal_entries` (`lines` JSONB array 2–100, balanced: a CHECK function sums debits and
   credits and requires exactly one positive side per line), `budgets` (`lines` JSONB 1–200, distinct accounts).
   Money `bigint` minor units; currency `^[A-Z]{3}$`; composite `(id, tenant_id)` references (institutions, calendars,
   parent account). ENABLE + FORCE RLS, `tenant_isolation`; `nexus_app` SELECT on all three, INSERT on
   `journal_entries` only (entries are never updated or deleted).
2. `GET /ledger-accounts`, `/budgets` (module `M19`, `m19.accounts.read`, insertion order); `GET /journal-entries`
   newest first (the mock prepends).
3. `POST /journal-entries` in the mock's order: module → `m19.accounts.manage` → body (`400`, detail paths = input
   keys in contract order, "Invalid journal entry field"; none for unknown keys or bad JSON; balance and one-side
   rules only after every field parsed) → institution of the tenant (path `institutionId`, "Invalid institution") →
   every line on an active account of that institution (path `lines`, "Choose active accounts for the selected
   institution") → insert `je-` id, `source: manual` → `201`. Audit `m19.journalEntry.created` (field names only).
4. Tests (real DB): lists and order; create + audit; each `400` (unbalanced, both sides, zero line, one line, bad
   currency, foreign institution, inactive / other institution account); guard before body; `module_disabled`; the
   balance CHECK rejects a direct unbalanced insert; tenant B isolation; forced RLS + grants; models match the schema.
