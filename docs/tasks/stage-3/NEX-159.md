## Goal
The prototype can read message threads, notices, meeting slots and bookings, each viewer's role home and the
leader KPIs from MSW, tenant-scoped and permission-checked, through typed `@nexus/services` hooks.
(M86 rollover reads were built in NEX-157; portals M25–M27 read `/me/home` plus the hooks of earlier modules.)

## Build
1. `stage3-access.ts` (D75): add `m24.messages.read`, `m24.messages.send`, `m24.notices.read`,
   `m24.notices.publish`, `m24.meetings.read`, `m24.meetings.manage`, `m28.dashboards.read`. Roles: owner + admin
   all; teacher `m24.messages.read`, `m24.messages.send`, `m24.notices.read`, `m24.meetings.read`; guardian and
   learner `m24.messages.read`, `m24.messages.send`, `m24.notices.read`, `m24.meetings.read` (guardian only).
   Entitlements: M24, M25, M26, M27, M28 for every demo tenant.
2. `db.ts`: `messageThreads`, `threadMessages`, `notices`, `meetingSlots`, `meetingBookings` from the fixtures.
3. M24 handlers (GET only, `get()`, `list()` pages, `ofTenant` always, `found()` → 404 for another tenant's id):
   `/message-threads` and `/message-threads/:id/messages` — `m24.messages.read`, and **only threads where the
   viewer is a participant, for every role including admin** (a non-participant gets 404; no moderation view).
   `/notices` — `m24.notices.read`; with `m24.notices.publish` all; otherwise only `published`, not expired, whose
   audience is `everyone`, includes one of the viewer's family's active class groups (as in `handlers/m16.ts`),
   one of the viewer's role keys, or the viewer's person id.
   `/meeting-slots?staffProfileId=` — `m24.meetings.read`. `/meeting-bookings` — `m24.meetings.read`; with
   `m24.meetings.manage` all; staff only bookings of their own slots; guardians only their own
   (`guardianPersonId`). Booking `note` → `null` unless the viewer is that guardian or has `m24.meetings.manage`.
4. M28 handlers: `GET /me/home` (module M28, no permission: own data) → `RoleHome` built from the db:
   role `leader` if `m28.dashboards.read`, else `staff` / `family` / `learner` from the viewer's role profile;
   `learnerIds` = the family's learners (empty for staff / leader); cards with counts computed from existing
   collections (e.g. family: unpaid invoices, absences this week, unread messages, notices; staff: today's
   sessions, pending leave requests; leader: `kpi` + `alerts`); `href` a lowercase path; `titleKey`
   `m28.card.<kind>`. A viewer with no profile → 403.
   `GET /dashboards/kpis` — `m28.dashboards.read` → `Kpi[]` computed for the viewer's tenant (attendance rate %,
   fees collected and outstanding in minor units with the tenant currency (D9), open admissions, active learners);
   `labelKey` `m28.kpi.<code>`; `asOf` = now.
5. Services: one `useX()` hook per endpoint (pattern `modules/m13.ts`, keys in `keys.ts`), exported from `index.ts`.
6. i18n: `m24.permission.*`, `m28.permission.*`, `m28.card.*`, `m28.kpi.*` in en / hi / ta (D42).
7. Files ≤ 300 lines; no message bodies, notes or other personal data in errors or logs (G-6, V-7).
