## Build
1. Shared: `AcademicCodeSchema` `/^[A-Za-z0-9][A-Za-z0-9._-]{0,31}$/` (codes like `G5`, `BSC-CS`, `JEE-26`).
2. `ProgramKindSchema` `early_years | school_stage | degree | diploma | certificate | course | batch_program`;
   `ProgramSchema` `{ id, tenantId, institutionId, code, name, kind, durationYears (int 1–10, nullable for rolling
   courses), active, createdAt, updatedAt }`.
3. `YearLevelSchema` (grade / year / semester level) `{ id, tenantId, programId, code, name, order (int ≥ 1) }`.
4. `ClassGroupKindSchema` `section | batch | cohort | group`; `ClassGroupSchema` `{ id, tenantId, institutionId,
   campusId (nullable), academicYearId (an `AcademicCalendar` id), programId, yearLevelId (nullable for batches),
   kind, code, name, capacity (int 1–2000, nullable), homeroomStaffProfileId (nullable), createdAt, updatedAt }`.
5. `SubjectKindSchema` `core | elective | language | activity | lab | project`; `SubjectSchema` `{ id, tenantId,
   institutionId, code, name, kind, credits (number 0–60 in steps of 0.5, nullable), active, createdAt, updatedAt }`.
6. `SubjectOfferingSchema` (a subject taught to one class group) `{ id, tenantId, academicYearId, periodId (an
   `AcademicPeriod` id, nullable = whole year), classGroupId, subjectId, staffProfileIds (unique, max 10),
   weeklyPeriods (int 0–60, nullable), createdAt, updatedAt }`.
7. Refines: `updatedAt >= createdAt` everywhere (compare with `Date.parse`); unique `staffProfileIds`; credits a
   multiple of 0.5. Cross-record rules (codes unique per institution, a class group's year level belongs to its
   program, `periodId` belongs to `academicYearId`) are server checks — list them as a doc comment.
8. Every object `z.strictObject`; export `XSchema` and `type X`; named exports only; file ≤ 300 lines; no imports of
   other workspace packages.
