# NEX-207 — Build: DB + API for M21 exams (exams, papers, seat plans, hall tickets, revaluation)

## Goal
Exams, exam papers, seat assignments, hall tickets and revaluation requests are stored per tenant under forced RLS
and served by the real backend with the same responses, errors, family scope and order as the mock. Generating a seat
plan replaces the paper's seats atomically and is safe to replay.

## Build
1. Migration `0036`: `exams`, `exam_papers` (`room_ids` array ≤ 20 distinct, `HH:MM` times, `end > start`, max marks in
   halves), `seat_assignments` (unique per paper and learner, and per paper, room and seat label), `hall_tickets`,
   `revaluation_requests` (encrypted `reason`, `new_marks` iff `changed`). Composite `(id, tenant_id)` references.
   ENABLE + FORCE RLS, `tenant_isolation`; `nexus_app` SELECT on all five; INSERT and DELETE on `seat_assignments`
   only (a new plan replaces the old one).
2. Reads as the mock: exams, `/exams/:id/papers`, `/exam-papers/:id/seats` need `m21.exams.read` (`404` unknown);
   `GET /hall-tickets?learnerId=` and `/revaluation-requests` (module only, family scope as M18; decrypted reasons
   audited once per page as `m21.revaluationRequest.sensitiveRead`).
3. `POST /exam-papers/:id/seat-plan` in the mock's order: module → `m21.exams.manage` and active staff profile
   (`403`) → paper `404` → exam `404` → exam `planned` / `scheduled` else `409` path `status` → roster on the paper
   date in roll order → fill rooms in order up to capacity (null capacity takes everyone left), labels `A1`… →
   unknown room or too little capacity `400` path `roomIds` → replace the paper's seats → `200` first page of
   `Page<SeatAssignment>` (page 1, the contract's maximum page size, total). Audit `m21.seatPlan.generated` (counts
   only). Replay via the core `Idempotency-Key` guard.
4. Tests (real DB): every read and `404`; family scope; seat plan labels across two rooms and the overflow room,
   regenerate replaces, capacity and room errors, closed exam `409`, replay; reason ciphertext; tenant B isolation;
   forced RLS and grants; models match the schema.
