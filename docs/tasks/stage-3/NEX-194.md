# NEX-194 — M86 rollover screens: start a dry run, override decisions, confirm, roll back

**Status:** planned · **Owner:** — · **Branch:** task/NEX-194 · **Depends on:** NEX-208 (contract + mock), NEX-193
**Requirements:** M86, D76, D78 (Owner review point 3, approved change to the frozen M86 screen), D84, D42, WCAG 2.2 AA

## Goal
Staff with `m86.rollover.manage` can run the year-end rollover from the M86 screen: start a dry run, change a
learner's decision, confirm, and roll back inside the window. Viewers with read only see what they saw before.

## Build
1. Services: `useStartRollover`, `useChangeDecision`, `useConfirmRollover`, `useRollBackRollover` (POST / PUT as the
   API guide; each invalidates the M86 queries).
2. Page header: "Start dry run" for `m86.rollover.manage` → dialog (institution, from-year, to-year from the
   institution's calendars, carry-forward checkbox; field errors from `400` paths; `409` shown as "a run is already
   open"). The new run becomes the selected run.
3. Run actions (manage only): `dry_run_ready` → "Confirm rollover" with a confirm dialog that states the counts;
   `completed` inside the window → "Roll back" with a confirm dialog. Errors (`409`) shown inline, focus kept.
4. Decisions: a "Change" button per row while `dry_run_ready` → dialog with action and, for promote / detain, a
   to-year class group of the institution; reason key cleared.
5. Texts for every new label and the reason keys `m86.promotion.noYearLevel`, `m86.promotion.noTargetGroup`,
   `m86.promotion.ageEligibility` in en, hi and ta (D42). Keyboard and screen-reader use as the M18 / M15 dialogs.
6. Tests: visibility by permission and status, each dialog's happy path and errors, focus return.
